# 《游牧工坊》最小垂直切片地基

> 状态：**Foundation v0.33，三居民与玩家存读档**，更新于 2026-09-08。当前三名正式居民共用建造、水循环、生活决策、世界物品、沙尘故障、实体维修、有限路线驾驶、厕所实例库存与车外取水 / 清运 / 备件补给。原生 Agent、全员召回、多居民 v9 检查点、只读集合和居民选择已接线；玩家保存/读取/取消、原生身体约束与续玩工程验收已完成，Foundation PlayMode 100/100；仍是灰盒基础版，尚非 Gate 1 或体验平衡结论；B/S0 的近期顺序与限制见 §9。

## 1. 这一版到底证明什么

它只建立一条足够小、但穿过真实产品层次的玩家路径：

```text
玩家选择饮水站
  → 鼠标投射为毫米 / 0.1° 量化的 DeckPose
  → 可选位置、旋转吸附与可关闭可视网格
  → 纯 C# 有向矩形做越界 / 重叠预检
  → 复用采样缓冲预演候选落地后的连通区
  → 每个 InteractionGroup 独立判定：组内任一 Slot 可达即保留该功能
  → 越界 / 占地重叠是硬失败；候选或既有功能点不可达是仍可确认的软警告
  → 创建候选障碍并异步更新 NavMesh
  → 导航更新成功则原子提交；居民被覆盖时自动迁到最近可站立点
  → 取消、复位或更新异常才停用候选并二次更新回滚
  → 3D View 从设施记录派生表现
  → 口渴居民在多个候选交互位中选最短可达路径
  → 站内有水则就近饮用；缺水时先寻找唯一防漏水罐
  → 完整估算“取罐 + 实际 NavMesh 路程 + 装水 + 送达 + 必要时饮用”
  → 硬性验证防漏能力与容量，再由 Utility AI 对候选需求收益和命名成本评分
  → 每座饮水站按稳定实例 id 拥有独立 6 L 库存，并投影到 Inspector / 调试 View
  → 最多 2 L 水进入 5 L 水罐独立库存，随罐移动并在目标实例倒空；空罐记录精确设施锚点
  → 不口渴时以低优先级把每座站分别补到 4 L 目标库存，不额外饮水
  → 无必要任务时，空地漫步与原地发呆作为两个完整候选方案参与加权随机决策
  → 玩家可建造带三个备选 Slot 的观景画架
  → 低娱乐居民把真实路程、作画偏好和娱乐收益放进同一次 Utility 决策
  → 精确抵达并取得共享交互空间后才开始作画；移动阶段不提前恢复娱乐
  → 每份 300 mL 水先进入身体，再按可调玩法速率逐 mL 形成膀胱内容物
  → 体内库存暂满是可恢复的生理背压，不再成为永久 Block
  → 排泄压力达到阈值后精确前往旱厕，废物真实转移到厕所暂存桶
  → 如厕、直接饮水、搬水补货、散步与发呆共用一次决策快照和同一个 Utility 入口
  → 不可达或缺少防漏容器的高风险候选保留诊断，但不再把居民永久冻结为 Blocked
  → 建造切断携水目标时，目的库存容量 / 交互预留与路径一起原子改道；未取货任务释放后重选
  → 世界 Seed、生活日与绝对 Tick 投影唯一确定的沙尘窗口、强度和下个边界
  → 车辆水箱的磨损、维护欠账和积尘按天气边界精确分段累积
  → 三类来源共同改变风险率；故障只在预取样阈值被积分跨过时触发
  → “出水阀卡滞”阻止新取水，并安全释放故障前尚未取货的搬运预留
  → 居民从 maintenance-supply 取得唯一实体维修包，精确前往 service-valve 并投入工时
  → 成功时才原子消耗备件并开启新风险周期；取消或检查点恢复到精确来源
  → 清洁保养降低未来风险来源；修理不把旧设备变新
  → 连续状态、亚微风险余量、阈值、周期、故障、严重度和世界物品一起进入运行检查点
  → 暂停态 Harness 复用生产模拟步，跨 Seed / 固定步长审计轨迹、停滞、极值与水量守恒
  → 玩家指定有限路线端点，居民实际到达驾驶台后才授予驾驶权
  → 行驶中需求继续推进；必要生活需求、目标取消、物理离岗与读档均先停车
  → v5 保存精确路程 / 燃料与目标；读取后重新到岗，旧租约不恢复
```

这条路径同时穿过输入、Command、摆放规则、Model、实时 System、Unity 导航 Adapter、实体库存、居民行动、3D 表现、调试界面和自动测试。后续增加厨房、厕所、建造材料和 Utility AI 时，应扩展同一条脊柱，而不是再堆互不相干的演示脚本。

核心依赖方向：

```text
输入 View → Command → System → 纯规则 / Model

```

## 3. 连续摆放真值与建造事务

每个已提交设施只保存稳定实例 / 定义 id 与 `DeckPose`：甲板局部 X/Z 以毫米量化，Yaw 以 0.1° 量化，Transform 和存档 DTO 都从它派生。玩家可在运行时分别切换位置吸附、旋转吸附和可视网格；这些辅助不改写已摆好的设施，也不进入碰撞规则。正式位置档位为自由、0.2 / 0.3 / 0.4 / 0.6 m，非零档位共用甲板原点且都是内部 0.1 m 基础格的整数倍。它保证切换时没有原点漂移，但不会强迫已经位于 0.3 m 节点的设施也落在 0.4 m 网格线上；自由模式保持毫米级连续姿态并自动隐藏网格。

`NomadFacilityDefinition` 声明一个或多个有向矩形 Footprint，以及有真实容量语义的 InteractionGroup 和组内备选 Slot。例如一座厨房可同时声明“灶台”和“柜门”两个独立 Group；每个 Group 只要有一个 Slot 可达就可工作，不会因同组其他站姿被堵就误报功能失效。

拖动阶段先用 `ContinuousFacilityPlacementLedger` 做便宜、确定的越界与 OBB 重叠检查；它们是阻止确认的硬几何错误。几何通过后，`ContinuousDeckReachabilityProbe` 复用当前 NavMesh Agent 半径与有效 Voxel 尺寸计算居民净空，在 0.1 m 采样的八方向连通图上做保守 Flood Fill。Slot 只允许在 75 mm 内映射到最近采样点，并额外用候选与既有设施的连续 Footprint 检查真实居民净空；这消除了旧 360 mm 目标容差在甲板边缘或 45° 紧贴设施时“隔着障碍找绿点”的误判。候选占到居民当前位置时，预演会把居民起点迁到最近未阻塞采样点，因此小人不再“抢占”建造位。候选或既有功能点不可达只产生可修复警告，玩家仍可确认：

```text
幽灵通过硬几何预检（可能带可达性警告）
  → 候选 Collider + NavMeshModifier(Not Walkable)
  → NavMeshSurface.UpdateNavMesh
  → 更新成功：Ledger + Model + 导航障碍一起成为已提交真值
  → 居民当前点失效：采样最近可站立 NavMesh 点并重新规划
  → 重算每座设施、每个 Group 和每个 Slot 的派生访问状态
  → 取消 / 复位 / 更新异常：停用候选，第二次 UpdateNavMesh 恢复提交前世界
```

实时预检不在每次指针移动重建 NavMesh，也不修改正式 Ledger；采样缓冲按甲板尺寸一次分配并复用，设施预览最多表达 64 个候选 Slot。它是面向玩家的保守预演，已提交后的实际路径仍由 NavMesh 查询。可达性投影是可重建诊断，不进入存档；加载设施真值后重建 NavMesh 再导出。异步期间暂停模拟推进。取消或复位会等待当前 Unity operation 进入终态后再安全回滚，不会释放仍在使用的 NavMeshData。纯 Ledger 支持多甲板层；当前 Unity 导航 Adapter 刻意只接主甲板层 0，等真实楼梯 / Link 需求成立再扩展。

旧 `FacilityPlacementGrid` / `DeckPathfinder` 只保留为无场景的独立纯算法回归，正式 Foundation Runtime 不再引用它们。若后续也不再保护任何独立价值，应连同测试删除，避免维护两套摆放 / 导航真值。

## 4. 寻路与多人交通契约

正式 Foundation 的三名居民通过 `DeckNavigationUtility` 查询 `PathComplete`，从设施的候选 Slot 中选择最短可达路径，再由各自执行对象持有的 `DeckResidentMotor` 驱动真实 NavMeshAgent。个人 Model 与 View 根节点都代表脚底，业务投影统一到甲板 Y=0；表现与碰撞胶囊各自设置半高中心。普通散步允许宽松采样，设施交互仍使用约半个有效 Voxel 的窄端点容差。原生 Agent 必须先走到终点附近且目标没有另一居民，才允许最后不超过 0.11 m 的精确停靠校正；校正后的水平误差超过 0.02 m 就不开始交互。旧角点夹具的 2 mm 门禁保留为确定性路径证据，不冒充引擎停靠容差。个人读模型投影实际位置、剩余米数、朝向和等待时间，可视网格不参与导航。

移动现在保存的是 `FoundationResidentMoveIntent`：阶段、任务说明、设施功能、指定 InteractionGroup、优先设施和是否允许替代，而不只是一份很快失效的世界坐标。取水、送水、如厕、作画、备件托盘与维修阀会限定到各自功能组，不会因重规划偷换到同一设施的另一种功能点。建造提交会释放旧 Slot、重新查询首选设施；完全不可用时选择最近的同功能设施；暂时没有路线则进入 `WaitingForRoute` 并限频自动重试。资源与动作租约在这段恢复期保持一致，因而不会重复取水、消耗错物品或凭空丢货。长期多居民版本仍需给等待租约增加超时 / 让渡政策。

正式 Update 只读取真实 Agent 进展，并沿同一业务状态机结算。暂停立即冻结位置和朝向，取消清除目的地，复位/读档释放旧 Agent；建造导航重建保留居民所有者并重新绑定路径。同步 Soak 与显式确定性夹具仍沿角点快进，报告注明 `MovementMode=deterministic-corners`，作用域结束把原生 Agent 同步到快进后的业务位置。独立 [`NavigationInteractionSpike.unity`](../Assets/Game/NomadWorkshop/Scenes/NavigationInteractionSpike.unity) 继续保护柜门全周期互斥等正式场景尚未覆盖的交互。

当前使用 Agent 局部避让、CharacterController 身体约束与设施空间租约；业务只读取已经过碰撞提交的脚底。没有正在执行工作的闲人可以实际走开让位；散步与尚未开始的爱好连续 3 秒无进展则释放该可选活动并重评，不伪造到达收益。携物和正式工作保持原所有权，并逐人发布等待诊断；这不是任意窄路的无死锁保证。10–20 人压力、门口通行 token 和动画尚待具体任务验证。选型和证据边界见 [`nomad-workshop-navigation-interaction-design.md`](nomad-workshop-navigation-interaction-design.md) 与[三居民 C 阶段](nomad-workshop-three-residents.md)。

### 4.1 统一决策与极端冲突的当前契约

`NomadFoundationSystem` 已不再先调用如厕分支、再调用饮水分支、最后才进入休闲。它会在同一份需求快照上构造如厕、直接饮水、搬水补货、散步和发呆的完整方案，然后只调用一次 `UtilityDecisionEngine`。纯 C# 选择器的固定顺序是：

1. 硬可行性先过滤不可达、无容器、容量不足、环境不安全或能力不足的方案；
2. 可行方案按日常、紧迫、严重、危急四级动态后果分层，只让当前最高层进入仲裁；
3. 同层紧迫度差超出容差时，更迫近后果的方案优先；在容差内才比较完整路程、耗时、体力、资源和需求改善；
4. 日常层保留有界随机，紧迫 / 严重层使用极低温度，危急层默认确定性选择；
5. 可行的应急方案即使 Utility 为负也不被最小分数丢弃，使居民仍能选择最小伤害方案；
6. 选中后才由执行层取得设施 / 资源租约，预留失败回到重评，不让评分器拥有任务生命周期。

纯规则测试已覆盖“火灾危急层压过膀胱紧迫层”、“火灾方案不可行时不压住如厕备选”、“同危急层在容差内用完整效用决定”和“负效用逃生仍可选”。但当前场景尚未生成真实火灾、重病、求援或多人应急任务；这些测试证明仲裁边界，不等于应急玩法已交付。

## 5. 随时保存的检查点语义

v6 将厕所污物归属迁到设施实例：各自保存容量 / 内容，旧共享桶按稳定厕所 id 唯一迁移，不复制污物；无可承接厕所的非空旧桶、混合新旧记录与错误归属都在修改当前世界前拒绝。[停靠资源所有权](nomad-workshop-stop-resource-ownership.md) 记录迁移规则和回归证据。

v7 保存干河驿站有限水源和取水意图。装罐后、注入车辆前保存，会在快照中把水归还驿站来源，居民恢复至任务前甲板姿态，读取后重新规划；Capture 不改变现场。每次派遣至多 2 L，空罐召回不取水，装水后召回先送完该批。返回旧营地指令等待归车与实际驾驶到岗，随后关闭车外通路；重返 / 读档不刷新水源。暂时需结束取水再调整甲板布局，保护返回路径及检查点姿态。

v8 增加有限污物接收罐（初始 24 L 空容量）与清运请求。居民拆走所属旱厕的同一只密封桶，到接收口才提交桶内全部污物；装回前厕所停用且车辆等待。倾倒前的检查点保留桶内原内容，倾倒后的检查点保留驿站已接收量，两者均恢复桶到原厕所并重新规划。接收余量不足时不拆桶，重返和读档不清空接收罐；旧 v7 只初始化缺失的接收罐，保留水源状态。任何车外作业结束前都先召回再改甲板布局。

v9 增加备件初始化标记与补给请求；两只初始驿站维修包使用已有 WorldItems 记录身份和区域局部姿态。移动包不增减件数，维修完成才消耗；途中检查点归还原驿站位置，已交付包留在车辆托盘，已消耗包不复生。旧档仅在缺失初始化标记时建立初始物资，空列表本身不触发补货。地点作为明确的支撑实体参与身份 / 区域验证；车辆维护托盘没有位置时，居民不会取货。

v5 将首段旅途的路线身份 / 参数、微米位置、皮升燃料与目标端点写入 `Vehicle.Journey`，不再用早期宏观占位字段继续积分。旧版合法甲板存档在保留原有设施、库存与居民状态后，从初始地点开启首次旅途；驾驶权不恢复。精确往返与非法路线在修改世界前拒绝的证据见[首段驾驶接线](nomad-workshop-driving-integration.md)。

首版存档骨架已放入无 Unity 依赖的 `Simulation/Persistence`，并用 Runtime Command 接到框架现有 `IStorageUtility`。当前格式覆盖：

- 世界 Seed、模拟 Tick、车辆宏观位置、目的地、旅途进度和燃料；
- 已建设施与未完成蓝图的稳定 id、定义、甲板层、毫米位置、0.1° 朝向和施工进度；已建设施还保存磨损、维护欠账、积尘、风险阈值 / 累计值 / 亚微余量、故障周期、具体故障、严重度和触发 Tick；
- 每个真实库存及资源批次的位置、计量维度、基础单位容量 / 数量、状态和污染度；件数与 mL 不能混装；
- 居民位置、随身库存、饥饿 / 口渴 / 健康 / 娱乐 / 心情 / 疲劳 / 压力，以及当前任务、目标、InteractionGroup、Slot、阶段和进度；
- `OutcomeCommitted` / `MaterialsCommitted` 幂等位，区分“动画进行到哪里”与“物品或材料是否已经真正结算”。

“随时保存”指任何玩家可见时刻都能得到**一致业务快照**，不是序列化整块 Unity 内存。当前 `NomadFoundationSystem` 已能捕获与恢复世界 Seed、统一模拟 Tick、已提交设施姿态、车辆 / 水罐 / 每座饮水站 / 身体 / 膀胱 / 厕所库存、普通落位物品的支撑区域与局部姿态、居民位置与身心状态、低于 1 mL 的 nL 代谢余量、设施连续状态与风险轨迹，以及居民决策、膀胱机会、休闲效果和行动 id 的下一随机游标。捕获前所有设施先懒结算到根 `SimulationTick`；读取较早结算点时也只从其已保存阈值和亚微余量继续，不会重新抽取事故，当前天气则直接由已保存 Seed / Tick 重建。`SaveFoundationCheckpointCommand` / `LoadFoundationCheckpointCommand` 再组合通用存储 Command，完成真实 Foundation → JSON / 原子文件 → Foundation 的往返。

NavMeshData、路径拐点、局部避让速度、运行期资源 / Slot / 物品 Use Lease、材质实例和订阅仍不落盘。加载时按设施与物品真值重建 NavMesh、交互空间、可达性与表现，并让居民从 Idle 重新决策。若保存发生在直接饮水、如厕或爱好的未提交阶段，已连续发生的身心变化保留，尚未提交的资源结果与瞬时表现被丢弃；若水已经装进居民携带的唯一水罐但尚未送达，快照把水和空罐回滚到精确车辆水箱锚点。若维修包已被拿起但尚未提交维修，Use Lease 会把它恢复到维护托盘的精确来源姿态。两者都保持业务守恒，也不会序列化半个运行期租约。建造候选和异步导航事务同样只保存上一份已提交世界；同步加载会明确要求事务先回到 Idle，而不是销毁 Unity 仍在使用的 `AsyncOperation`。

已验证“版本化快照 → Command → `IStorageUtility` → JSON / 原子文件 → Command → 校验 → 重建”的真往返。Unity JSON 会把某些 `null` 嵌套 DTO 还原成全默认对象，加载准备阶段只把真正全空的 `ActiveAction` 正规化回 `null`；带任意身份或进度却标为 `None` 的矛盾数据仍拒绝。mL 迁移曾把协议升为 v2；正向娱乐 / 心情把协议升为 v3；健康与死亡真值把协议升为 v4，旧 v3 居民按当时“不会死亡”的实际语义迁移为完全健康。新增代谢余量使用有效的零缺省，因此未制造无意义版本升级。设施状态同样使用“全部新字段为零”作为无歧义的早期 v3 缺省：旧存档保留耐久 / 脏污投影，并从读取 Tick 开启新风险周期，绝不补猜过去未记录的暴露；只有部分新字段存在会被当作损坏数据拒绝。旧 v1 的无量纲 `Amount / Capacity` 仍明确拒绝而不猜测迁移。**尚未完成**玩家存档 UI、自动保存节奏、多槽管理、未完成蓝图恢复、多居民恢复顺序和“从动画中间继续”的表现层能力；当前检查点刻意恢复到最近业务安全边界。

## 6. 当前可操作方式

执行 Unity 菜单 `Assets/SSFramework/游牧工坊/Foundation/创建或打开最小垂直切片`，或打开 [`NomadFoundationVerticalSlice.unity`](../Assets/Game/NomadWorkshop/Scenes/NomadFoundationVerticalSlice.unity) 后进入 Play：

- 数字键 `1–3` 或左侧按钮选择饮水站、野战厨房、旱厕；
- 鼠标连续移动建造幽灵；左键确认；右键逆时针旋转；`Esc` 或面板按钮取消；
- `Q / E` 也可按当前角度步长旋转；位置吸附提供自由、0.2 / 0.3 / 0.4 / 0.6 m，默认 0.2 m；自由模式无位置网格，其他档位的网格线同步使用当前步长，旋转默认 45°；
- 中键拖动环绕甲板，滚轮缩放保留人工试玩调整后的 `1.0 m / 输入单位`；触屏双指质心拖动对应旋转、指距变化对应缩放。镜头限位与姿态算法共用，鼠标和触屏因输入单位不同而分别配置灵敏度；
- 候选幽灵旁会显示各交互位；绿色表示实时保守预检可达、红色表示不可达，面板同步显示本次耗时和访问格数；
- 建造视图中，无需悬停就持续显示所有既有设施的全部 Slot；完全不可达的设施标红，只有部分功能可用的设施标橙，每个失去全部可达 Slot 的 Group 还保留独立红色功能警示；
- 可达性警告不禁止左键确认；越界、占地重叠、重复身份或导航更新异常仍是硬失败；
- 默认左上角只显示居民 01 的水分 / 健康 / 精力 / 心情紧凑卡，长任务说明可完整换到第二行；右上角“居民详情 / 建造 / 开发”共用一个互斥面板槽，不会叠出多个窗口。建造面板只显示设施、吸附、预览和可达性控制，开发面板只显示模拟真值、方案、资源、设施状态与 Harness，不再呈现同一整份内容；世界点击只拦截实际可见卡片 / 工具条 / 展开面板；
- 开发控制台中的 Harness 可暂停、切换 `0.5× / 1× / 4×` 和确定性复位；
- 暂停且没有建造事务时，可一键快进六个生活小时：输入按 100 ms 分块，内部与实时路径同样按 10 ms 执行和审计；报告版本、Seed、停止原因、极值、故障、行动、停滞、守恒和逐步轨迹。单次最多 200,000 个实际业务步（2,000 模拟秒），死亡或停滞在当前业务步结束，不补满外层分块。输入分块可为 10–1000 ms 的任意整数，总时长必须整除 10 ms；
- 同一开发面板持续显示当前天气 / 强度，以及车辆水箱的等效磨损、维护欠账、积尘、风险进度 / 速率 / 阈值、具体故障和严重度。每个十分钟生活日会由 Seed 决定一场 90 秒沙尘；正式故障后，居民会从 `maintenance-supply` 维护托盘取得实体维修包，精确抵达 `service-valve` 并工作，完成时才消耗备件。“Harness 沙尘冲击 / 瞬时修理”等按钮只保留为快速、可审计验收捷径，不是玩家动作；
- 开发控制台和 `NomadFoundationModel` Inspector 持续显示唯一已提交 `SimulationTick`、24 小时生活日与气候相位；移动、动作、生理和需求每次只消费固定 10 ms。墙钟小数余量和未执行预算跨帧保留，每帧最多追赶 100 步；暂停和导航事务不继续入账或执行。复位 / 读取清空未执行墙钟预算，只恢复已发生的业务时间；
- 建成饮水站后，口渴居民会先取得画面中唯一的 5 L 防漏水罐，再装入最多 2 L、搬运到选定实例并饮用 300 mL；倒空的水罐记录该实例锚点，因此下一次补货会去正确设施取罐，各站分别补到 4 L 后不会因此连续喝水；
- 开发控制台与 `NomadFoundationModel` Inspector 会同时显示全部饮水站合计、逐实例库存、水罐位置 / 精确锚点 / 内容，以及最近完整方案的步骤数、真实路径、估算时长、行程 / 动作 / 体力 / 风险成本、动态风险层 / 层内紧迫度、选中概率和 Utility 总分。
- 水需求暂无必要任务时，居民会在可达空地闲逛、原地发呆，或使用已建造的观景画架；没有画架时基础偏好经同一 Softmax 形成约 1:2 的闲逛 / 发呆比。前两者不占用硬性 InteractionSpace，也不恢复娱乐；画架候选会估算真实 NavMesh 路程与个人作画偏好，取得 `paint-and-observe` 共享空间并精确停靠后才连续恢复娱乐、略微改善心情与压力。社交和其他爱好仍未实现。
- 膀胱如厕意图已从 58% 硬阈值改为通用平滑压力曲线：50% 及以下概率为 0，50%–90% 非线性上升，90% 起成为必处理的紧急需求。确定性样本只在主行动决策边界消费，不按帧反复掷骰；曲线原语已可供其他需求复用。
- 体内水暂满时面板可能短暂显示 `DestinationFull`，它表示正在等待代谢或排泄，不再是永久停机。建造可达旱厕后，居民会自动前往并把排泄物真实留在所属桶；干河驿站可派遣清运，接收罐必须能容纳该桶全部内容。满膀胱且厕所满桶时，清运作为恢复如厕的前置工作仍可执行。
- 底层以整数 mL 保持守恒，面板按数值显示 mL / L。默认车辆水箱容量 100 L、初始 60 L，每座饮水站容量 6 L、体内待代谢容量 900 mL、膀胱容量 500 mL、当前共享旱厕暂存 12 L；这些容量和速率是首轮可玩性假设，不因单位拟真就冒充现实生理结论。
- 纯 C# 时间 / 随机 / 环境 / 风险地基已进入首条正式后果链：统一模拟毫秒已接管当前 Foundation 的 `Update` 并投影生活日与压缩气候相位；天气由 Seed / Tick 确定，设施暴露在天气边界精确分段；Utility AI 使用领域隔离的稳定样本槽，运行检查点恢复各随机流下一事件序号，不会加载后重掷同一结果。车辆水箱“出水阀卡滞”会阻止新取水并释放尚未取货的任务预留，普通视图持续标红；居民真实维修已接入，但目前只有一个简单周期天气、一种故障；初始包和驿站两只包可支持后续维修，尚无制造、维修工具与专用动画、其他设施故障谱和玩家存档界面。

厨房目前只验证同一连续摆放数据、必需 Slot 与 3D 替换接缝，尚未接入生产。旱厕已接通“膀胱 → 设施实例桶 → 停靠接收罐”；拆卸 / 回装移动容器本身，只有倾倒才转移内容。旧 [`FoundationResourceFlowSpike.unity`](../Assets/Game/NomadWorkshop/Scenes/FoundationResourceFlowSpike.unity) 的单体 Controller 继续作为历史物质链参考。

Foundation 当前已有正向娱乐 / 心情与负向疲劳 / 压力的独立连续运行状态：发呆和闲逛只缓解休整项，娱乐继续衰减；观景画架已打通首个真实爱好恢复，高娱乐最多把疲劳增长放缓 18%，低娱乐会连续影响心情和压力。每次休闲效果倍率只在行动开始时确定性采样一次。姿势不适、睡眠、社交、多居民爱好档案，以及主行动 / 微活动 / 检查点绕行执行器仍未接线，不能把一个画架误写成完整生活模拟。

首轮长跑揭示了此前短测试没有覆盖的量纲错误：`residentPaintingAffinity=0.34` 原本被直接加到 Utility，而散步整项方案只有约同量级的一半，导致画架存在时散步在 Softmax 之前就被短名单淘汰。现在候选保留 0–1 人物偏好，政策再以有界比例映射成效用；娱乐缺口仍独立形成真实需求收益。采用接近正式的 3.5 秒基础休整、8 秒作画和 2.8 m/s 路速后，四个 Seed 的六生活小时样本均同时出现发呆、散步和爱好，画架不再垄断；这些数字只证明退化被抓住和轨迹可比较，不是最终平衡结论。

检查点长跑遵守现有存档语义：捕获会把半个路径、动画和未提交资源 / 物品租约回退到最近守恒业务边界，而不是承诺与未读档画面逐帧相同。同一中途检查点经两次完整恢复后，后续 90 秒的逐步轨迹校验和、各行动增量和水量偏差完全一致，证明派生 NavMesh、库存、设施状态、世界物品与随机游标重建后仍可确定继续。相对不中断分支的业务预算也已有明确门禁：刻意在行动 20%–80% 捕获时，90 秒内完成行动差不超过 1，健康 / 口渴 / 娱乐 / 心情 / 疲劳 / 压力差均不超过 0.005；若未来扩展执行器突破预算，应先解释差异而不是偷偷序列化整段瞬时表现。

### 玩家手动存读档

旅程面板顶部提供一个手动槽的“保存旅程 / 读取旅程”，进行中可以“取消等待”。保存覆盖该槽旧进度，读取替换当前旅程；进行中的路径、动画与未提交搬运按已有守恒检查点规则重新安排。操作期间暂停，结束或取消恢复操作前的暂停选择。

System 拥有当前操作，异步 Command 只借用存储并在 IO 返回后核对所有权。外部复位、取消或 Context 销毁撤销旧操作；迟到结果不能覆盖新世界或替新操作写反馈。建造导航事务与存读档互相拒绝跨入，当前操作不会静默丢弃半个建造事务。缺档/主备都不可用保留当前世界；不兼容或重建失败提供原因，重建失败沿用原有守恒回滚。取消保存不保证撤回已经原子提交的文件。

验证使用临时 GUID 目录中的真实 FileStorageProvider，含物理完成等待门，覆盖取消后仍返回旧字节的路径；不改玩家存档与框架公共返回类型。专项与完整旅程证据集中于[三居民接线 D](nomad-workshop-three-residents.md)。

Soak Harness 当前为 **0.10.0**，明确标识 `MovementMode=deterministic-corners`：极值和完成次数统计全员，轨迹包含每人的身份、状态和库存，守恒涵盖车内、人体与有限地点，初始总水量 **80,000 mL**。checksum 不跨版本比较；全局“有进展”不能证明每人都未卡住。原生测试通过逐帧观察个人移动等待和每个任务的有界完成时间补足交通证据，仍不等于任意布局无死锁或完整旅程体验成立。

| 场景 / 工具 | 当前定位 | 退出条件 |
|---|---|---|
| `NomadFoundationVerticalSlice` | 持续演进的产品地基，保留 | 被真正可玩的产品场景完整接管并拥有等价回归后再迁走 |
| `NavigationInteractionSpike` | 导航 / 拥堵 / Slot / 交接 Harness，保留且不进 Player Build | 正式多居民夹具以更低成本覆盖同等不变量 |

| `UtilityAiSpike` | 决策可解释性实验室，暂留 | 正式居民调试器能显示同等候选分解、Seed 与选择结果 |

隔离 Spike 不承载玩家正式进度，也不写默认存档槽；正式 Foundation 仅在玩家手动保存时写入旅程槽。场景不因为名字叫 Spike 就永久保留。一旦生产测试提供更便宜的等价证据，就按退出条件删除，避免双重维护。

### 开局成长方案的实现依据

这条队列不是从零发明一套平行系统，而是把当前已验证接缝重新组合：`NomadJourneySession` 已经拥有路线、燃料、目标版本和确定性推进；N0 已在其上接入 8 m/s 巡航、纯规则加减速、速度 / 积分余量快照和锚点目标，旧的 10 m/s 恒速 Foundation 检查点会在路线身份与油耗仍匹配时迁移到当前策略。锚点目标只保存稳定 ID，实际位置仍由当前路线定义解析，避免把兴趣点坐标写死进存档。`FoundationEnvironmentPresentation` 已按车辆坐标滚动地表，适合扩展为局部地表片段环和远景壳体，而不是创建一张无限 Terrain。`ResourceInventory`、`ResourceFlowLedger`、`NomadWorldItemDefinition` 和现有世界物品搬运已经能表达资源批次、容量、地面支撑和居民携带；N2 应补充蓝图材料暂存、施工工作量、设施拆除回收、车内外支持面和取消 / 回滚边界，不绕过库存直接修改数量。正式 Foundation 目前已有驾驶租约、食材、成品餐、污水和人体污物的资源 id，N3 可在此上面增加接力交接状态，N5 可复用生活链做第一顿共享餐；芯片、打印介质和交易券再以同一 `Item` 计量维度加入，不为螺丝建立独立模拟。

车辆承载、发动机和蓄电池尚未进入当前 `NomadVehicleSaveData`，因此 N3 必须新增版本化车辆进度字段并定义“车辆库存 / 居民携带 / 地面堆 / 设施库存”四种所有者，不能把重量从 Prefab 名称或渲染堆放反推出来。统一建造需要把 `SupportSurface` / `PlacementRegion`、蓝图施工暂存区、可达工作姿态和地点范围接成一条事务，不需要再引入工作台设施；节点设施进入长期站点状态，途中设施只在距离阈值内保留，车辆设施随车辆移动，不能为每个荒野物件建立永久档案。研究台只是可选研究设施，复用已有放置区域承接纸、笔和水杯等物品，不成为基础建造前置。居民姓名、性别和外观种子已在 N1-A 进入 `NomadResidentSaveData` 与首位 Model 记录；旧档使用空身份，新的伙伴原型仍应沿同一稳定字段扩展。拆解和随机事件必须沿现有 `NomadWorkshopSaveData` 的世界种子、随机流和版本迁移工作，先写纯 C# 规则测试，再接场景和可替换资产。

车上资源的第一版表现建议采用少量有身份的货物锚点：箱、捆、油桶和盖布按库存 / 重量分层显示，装满后改变轮胎下沉、发动机声音、车厢拥挤或可用通路；不把每件材料生成成没有玩法意义的散落网格。设施拆除后先在停靠场景中生成可搬运货堆，只有搬运事务提交成功才进入车辆库存；这同时满足废土拾荒的视觉叙事、资源守恒和存档可恢复性。

### 本轮需求审查结论

- **3D 打印不是第二套建造系统**：它只是一种带输入资源、耗电、耗时和稀有控制芯片的设施加工行动；打印完成的零件仍通过普通搬运和蓝图施工装入设施。
- **第一台打印机不从零制作**：推荐从废墟找到损坏设备或从商人处购买，芯片既稀有又不可打印；否则会出现“需要打印机才能制造打印机”的递归门槛。
- **交易保持一层深度**：一个交易媒介、有限货架、固定报价、真实库存和确定性补货足够表达商人摊位；动态价格、议价、区域经济和多货币以后再评估。
- **大地图采用大逻辑范围而非巨型单体地形**：路线进度可以很长，镜头内由地表片段环、远景壳体和雾尘完成连续感；所有可交互兴趣点用路线锚点保证可达。
- **接力驾驶是驾驶租约转移**：当前驾驶员保持速度直到接班原子提交；没有候选人时仍保留安全停车，不能让“接力”变成无限续航漏洞。
- **温馨与张力分层**：氛围、动作和镜头提供温馨感；软压力让休息、娱乐和研究成为长期必需；资源断裂、故障、天气和敌对事件才提供硬危机。

本轮暂不承诺实时战斗、完整捏脸编辑器、无限对话生成、三四层同时可玩、完整大陆级地图或所有居民都能随意离车。危机应该改变选择与节奏，不能把日常旅途变成连续警报；实际试玩若证明某项家务只增加等待，就合并为协同任务或降低自动化频率。
