## 已观察到的边界

世界只拥有一份资源、物品放置、设施交互空间和旅途账本。居民拥有自己的执行对象和 Model 数据记录，执行对象明确引用对应记录。只读查询绑定记录中的同一批 R3 属性；复位或恢复原居民时不替换这些属性，避免 View 继续订阅旧对象。禁止在遍历居民时临时交换全局 Model 属性来伪装个人状态。

建造反馈留在世界 Model，居民任务和阻塞留在个人记录。居民集合使用 `ObservableList`；WorldView 复用 Framework 的 `ReactiveListBinding`，每行拥有自己的 R3 订阅和表现资源。HUD 可以选择居民，旅程面板同时显示全员状态；开发杯具命令携带所选居民的稳定身份。

## 移动与 Harness 证据

沿用[导航设计](nomad-workshop-navigation-interaction-design.md)的 NavMeshAgent 局部避让；不为了同步快进测试另造全甲板格子预约或第二套人群模拟。正式 `AdvanceResidentAlongPath` 现已接入原生移动对象，只有同步 Soak 和显式配置的确定性规则夹具使用固定步角点移动。两者共享业务状态机、物品与资源账本。

资源守恒、租约互斥和检查点可用确定性业务步验证。原生 Agent 由 Unity PlayerLoop 推进，人群交通必须通过真实帧观察同一正式执行器；同步 Harness 的数量/轨迹不能冒充 Agent 会车证据。接线时需分别记录两类范围，并验证实际位置变化不会让偶然帧序造成重复领料或重复提交。是否需要新增异步观察 Harness，以该接线的实际阻碍为依据，不提前扩张通用工具。

### C 阶段的实现与验收顺序

1. 原生 Agent 由导航 Adapter 创建，居民执行对象拥有其运行期生命周期；View 继续只消费个人位置投影。取消行动停止物理移动，移除居民/复位则释放 Agent，不能留下旧实例继续走路。
2. 正式 Update 读取真实 Agent 进展，沿同一行动状态机完成停靠与提交；验证暂停、1×–4×、导航重建及读档。同步 Soak 的角点快进保留明确的测试模式标识，不能生成原生交通的通过结论。
3. 用正式三人场景验证会车、闲人让出已被领取的工作位和窄路恢复；逐人记录目标、实际位置和无进展时间，避免其他人的活动掩盖某一人卡住。身体等待不能导致重复领料或漏回滚。
4. 再运行三人有限停靠、召回和返程。实际 PlayerLoop 无法在同一调用里同步推进时，增加有界异步观察入口并复用现有业务投影/守恒统计，不另造模拟世界。

### D 阶段的玩家检查点边界

首版提供一个明确命名的手动旅程槽，玩家能直接“保存旅程 / 读取旅程”，看到进行中、成功、缺档或失败原因；多槽、自动保存和云同步不作为当前前置条件。继续复用现有 checkpoint 与 `IStorageUtility`，View 只发 Command，不负责 JSON、磁盘路径或世界重建。

存储操作暂时暂停世界并阻止重复操作，结束后恢复操作前的暂停选择。操作状态属于当前世界：复位、Context 销毁或取消会撤销操作所有权，迟到的读取不能覆盖新世界，旧回调不能给新局写“成功”或擅自解除暂停。恢复失败维持原世界；原生 Agent 与路径由恢复后的居民执行者重新创建，不能续用旧物理实例。

验收应同时包括真实存储往返、缺档/损坏反馈、慢 IO 时复位或取消的迟到完成，以及从保存点继续一次原生三人旅途。正在导航建造时需明确反馈等待安全边界，不把半个建造事务静默丢弃。

框架的 `Load<T>` 返回空值表示“没有可用存档”，同时覆盖缺档与主备均无法反序列化；`Exists` 只是文件存在快照，不能证明存档健康。玩家主动读取失败时保留当前世界，不能照搬新玩家启动示例的“空值就开新局”。此需求可以由现有存储能力和业务操作所有权完成，不需要修改框架的公共返回类型。`LoadFoundationCheckpointCommand` 的 false 注释已同步为“没有可用存档”，包括缺档及主备均损坏。

异步编排仍留在 Command：通过 `ctx` 调用现有存档命令并透传取消令牌。System 持有本次检查点操作及暂停状态，Command 在每次 IO 返回后确认操作仍属于当前世界，再提交恢复或显示结果。自身读档重建要显式携带该操作所有权，外部复位/直接恢复则撤销旧操作；不能用一个临时全局布尔值绕过所有复位。View 只观察进行中和反馈、发出保存/读取/取消命令，并观察异步异常。慢 IO 用可控 Provider 验证真实取消和迟到返回边界，不通过延迟 UI 文案来伪造。

### D：当前实现与定向证据

旅程面板已提供“保存旅程 / 读取旅程 / 取消等待”，明确提示一个手动槽的覆盖语义。`CheckpointBusy` 与 `CheckpointFeedback` 属于世界只读投影；View 发 Command 并观察异步异常。`CheckpointOperation` 由 System 持有，保存操作前的暂停选择、Context 生命周期和本次取消源。命令在每个 IO 返回点复核当前所有权；自身读档显式携带同一个 owner 穿过重建与回滚，其他复位/恢复撤销旧 owner。Context 先销毁时不再发布运行 UI 通知；CTS 在命令物理完成后释放。

### C：移动所有权与证据

正式 `DeckResidentMotor` 由居民执行对象持有，负责目的地、暂停、停靠和物理释放；`DeckNavigationUtility` 只创建并配置实例，不把动态居民塞进隔离实验的序列化目录。View 不取得 Agent，也不写入物理位置。行走由原生 PlayerLoop 推进，Agent 提议位移，CharacterController 约束并提交脚底；初始化、恢复/建造迁移和显式快进后同步允许位置迁移，末段停靠也经过身体约束。恢复行走前还会在**同一脚底**重新锚定内部模拟位置，这不移动居民或完成业务任务。

停止沿路径前进不等于固定工作位。Adapter 始终解除 Agent 的位置/朝向自动耦合，以 CharacterController 独占实际位移；静止时固定脚底并使用优先级 0，移动时全员使用优先级 50。身体碰撞限制位移或恢复行走时，把内部模拟重新对齐到同一脚底并保留原目的地。其边界来自实际取水场景：`isStopped=true` 的作画者曾被避让推离工作位。只依赖 `nextPosition` 赋值还出现过 0.39 m 恢复跳动。参考 Unity 的 [updatePosition](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AI.NavMeshAgent-updatePosition.html) 和 [nextPosition](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/AI.NavMeshAgent-nextPosition.html) 契约。

原生等待按剩余路程取得新最小值计时，绕圈位移不清零等待。闲人可通过正式意图实际走开；散步和**尚未开始的爱好**连续 3 秒无进展后释放自己的可选活动并重评，不发放完成收益。正在执行的工作和携物任务保留原契约。这解决了往返中未开始的作画与补水互等，不构成任意窄路的通用无死锁证明。

2026-09-08 的 HUD 回归进一步暴露完成工作的短窗口：只由等待者每两秒尝试让路，可能错过“作画完成 → 空闲 → 再次领取工位”，导致附近驾驶员持续等待。当前原生居民在 Idle/WaitingForFacility 的正常决策时机，先回应已有的近处通行等待，再选择新行动；复用同一候选与整段身体净空检查，失败搜索沿用原决策重试间隔，不在每个 10 ms 业务步反复计算路径。正在工作或持有任务/空间租约者继续受既有保护，完成收益只由真实工作完成结算。同步 Soak 不执行此分支，存档不新增等待请求字段。

定向夹具先让居民经真实决策与租约进入作画，再控制“等待者刚轮询完、作画下一步结束”的交错；修正前拒绝，修正后观察到主动让位、真实驾驶到岗与准确完成次数。原失败、几何对照、该时序的红/绿证据与最终阶段回归统一见[首版 HUD 验证](nomad-workshop-hud-first-pass.md)。原生运动仍受真实帧时长影响，不把固定 Seed 的一次通过当作所有时序均安全。
