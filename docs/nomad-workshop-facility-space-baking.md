# 设施模型空间生成实验

接续 `35a1201`，实现[模型交互绑定](nomad-workshop-model-interaction-bindings.md)的 P1。当前站位、支撑区域和占地在定义资产中手动维护，模型上的标记不会更新这些真值；存档也不能区别同一个设施 id 的空间版本。

## 本轮计划

- [x] 用自有 Prefab 的显式矩形/支撑面标记和现有交互组/Slot 组件生成米制定义快照。坐标统一到设施根；支持合法的不同父级变换，拒绝倾斜支撑面、非平面站位、剪切、反射和无效尺寸，不用 Renderer 总包围盒推断实物。
- [x] 生成器先构建和校验候选，再提交定义。保存空间内容摘要，启动时同时检查模型标记和已生成定义；过期或未生成的绑定不能进入玩法。
- [x] 检查点记录已生成设施的空间摘要；空间相同允许只换美术，空间不同时在世界修改前拒绝。旧档没有摘要时，只有与首次生成前的明确基线一致才兼容，不静默抬高或挪走物品。
- [x] 用水设施的独立变体改变站位、支撑区尺寸/高度和可见托盘，跑同一真实工作路径。验证同组多个候选仍共享容量、不同组可以独立预留，以及新旧区域身份和存档兼容。
- [x] 执行改动对应的 EditMode、保存契约与实际场景回归；检查真实画面，记录恢复状态和限制后阶段提交，再继续参考图设施造型。

本轮继续使用单层 DeckPose 与有向矩形，不提前引入可攀爬多层、任意 Mesh 桌面采样、永久开门状态或同时多管线操作。多层身份承接已有甲板方案；不同交互组的业务能力选择仍属于 P2 后续，增加候选点不等于新增并行工作能力。

## 制作与替换入口

`FoundationFacilitySpaceAuthoring` 放在自有模型 Prefab 的根上。根保持单位缩放；需要调整导入模型比例时，在内部子树缩放，再校准标记。根内的显式引用声明占地矩形、现有 `FacilityInteractionGroup` / `FacilityInteractionSlot`，以及区域矩形、支撑高度、边缘内缩和物品类别。标记可以来自不同父级，生成时统一转到设施根坐标；局部非均匀缩放可以改变矩形尺寸，产生剪切或倾斜则拒绝。站位 Y 必须在毫米量化的零平面，支撑区域保留独立高度；内缩按根空间的米数解释，不随非均匀缩放变成两个值。

模型上的 `FoundationFacilityArtRig` 继续拥有动画接触点、分件、行程及工作阶段绑定。静态区域不随门盖动画逐帧重算；本轮复用的 Slot 组件只提供空间身份和姿态，组件中的动作语义和贴靠容差未新增为 Foundation 的能力解析配置。

在非 Play 模式保存模型 Prefab 后，选中 `NomadFacilityDefinition`，执行“Assets/SSFramework/游牧工坊/从模型生成选中设施的空间”。生成器先复制临时定义，将模型空间写入候选并核对 ArtRig；全部通过后才提交、保存原定义。失败不部分覆盖定义。新建空白定义也能直接生成，不必先手填一份虚假空间；没有有效旧空间时，不授予无版本旧档兼容资格。

测试用变体由“Assets/SSFramework/游牧工坊/首版美术/生成并打开设施空间变体”重建。场景为 `Assets/Game/NomadWorkshop/Scenes/FacilitySpaceSample.unity`，沿用当前参考车体、环境、HUD 和三居民；两份 `NW7_` 水设施 Prefab / Definition 位于 `ArtFirstPass/`，保留原设施 id。取水与饮水/交付站位向外移动 0.06 m；水箱维护区域从 0.52 × 0.34 m、1.42 m 高变为 0.60 × 0.40 m、1.52 m 高，并增加对应的可见托盘及支脚。原水罐停车区和业务组 id 保持。这是接线实验，旧设施网格和新增简化托盘仍需后续造型，不把它视为参考 J 的美术定版。

## 空间身份与保存边界

空间摘要按现有模拟的毫米 / 0.1 度量化，涵盖占地几何，交互组/候选和区域的稳定 id、大小、朝向、高度、内缩和类别。保留数组顺序，因为它可能影响候选选择。摘要不含网格、材质、对象名或世界位姿；单纯替换外观且保持这些空间真值时可以延续保存。System 与 WorldView 初始化均核对模型输入、生成摘要和定义数据，未生成或过期时给出明确错误。

`NomadFacilitySaveData.SpaceSignature` 为 v9 的可选字段，空值保留旧档含义；保存契约检查非空摘要的格式，Foundation 在恢复事务写世界之前检查兼容。规则为：有摘要须与当前生成摘要相同；无摘要仅允许仍未接入的旧定义，或空间等于首次生成前记录的有效基线。改变空间后重复生成不会重新认领旧档；不兼容需要另做明确迁移，本轮没有自动迁移器。该保护只覆盖已接入生成的设施，不声称旧手工定义已经获得版本保护。

## 测试发现的组容量缺口

首轮空间 EditMode 为 12/13，失败显示同组候选相距超过 0.35 m 时可被两名居民同时预留。原 `FoundationInteractionSpaceRuntime` 只占用几何聚类后的 Slot 键，动作自己的资源键不能完整替代模型声明的组容量。

修正为一次原子租约同时预留“实际选择的设施组”和“所处空间的全部 Slot”。同组远端候选互斥；不同组、不同空间仍可独立工作。不能简单合并同组所有几何空间，否则会通过未选择候选传递锁住其他工位。占用显示、可用查询与拓扑重建使用同一规则。新增测试覆盖远端候选、共享站位、另一组远端站位、重建保留与释放后再预留；原空间租约生命周期测试继续执行。

## 下一轮代表设施造型

再次打开 J 和本轮实机后，差距主要仍是旧设施的大块单色与简化轮廓。先以水箱/饮水站深化罐体端盖与支承、折边机柜、内凹操作面、阀门/盖板真实分件；灰米结构、低饱和旧青绿与局部暖光保持辨识度，减少大块亮橙色。按实际 UV 烘焙可进入 Unity 的旧漆和磨损，而不是只改善 Blender 预览。

先替换这组已接线设施，在相同场景镜头/光照下检查尺度、身体/携物接触和造型，再推广到厨房等设施。站位、区域、接触点与机构按本轮组件配置，不为新网格另写业务行为；本轮新增托盘只是空间实验，不继续把原始盒体装饰成最终资产。紧凑楼梯、局部扩建与两层携物仍保留在主队列，未因 P1 完成而被取消或视为已完成。
