## 判断依据

当前应保留的方向：管理者下意图、居民自主执行；宏观航向与车辆局部坐标分离；单层连续建造；选择性真实；有来源、目的地与容量的资源流；确定性事件；按业务安全边界保存。它们已经共同支撑真实建造 → 导航事务 → 搬水 → 饮水 → 排泄，以及故障 → 取实体备件 → 到位维修。

真实调用路径是 `View → Command → NomadFoundationSystem → 纯规则 / Model → 只读投影 → View`。`ResourceFlowLedger` 与 `PlacementRegionLedger` 拥有资源、空间和租约；`DeckNavigationUtility` 拥有 Unity 导航操作；Foundation System 拥有任务、取消和恢复。遵循 ADR-0001 / ADR-0014，当前没有证据要求修改 Framework 或引入通用任务框架。

## 本轮时间推进方案

复核入口：[实时推进、候选与厕所库存](../Assets/Game/NomadWorkshop/Runtime/Foundation/NomadFoundationSystem.cs)、[实体维修](../Assets/Game/NomadWorkshop/Runtime/Foundation/NomadFoundationSystem.Repair.cs)、[检查点适用边界](../Assets/Game/NomadWorkshop/Runtime/Foundation/NomadFoundationSystem.Persistence.cs)、[正式行为回归](../Assets/Game/NomadWorkshop/Tests/PlayMode/NomadFoundationVerticalSlicePlayModeTests.cs)。这些证据优先于专题文档的旧“待接入”描述；导航文档中同样过时的运行检查点 / 水罐放置区状态已同步修正。

比较两种实现：让每个行动精确计算跨阶段余量，或先统一固定步推进。前者能精确处理事件，但需要同时重写移动、工作效率、代谢、故障与所有中断边界；后者能在现有单 owner 后收口帧率差异，迁移面较小。因此先采用固定 10 ms 业务步，保留现有行动语义与量化误差。

墙钟只贡献待处理预算；只有一次业务步实际执行时，统一 Tick 才前进。积压不丢弃，也不通过一次巨大的 delta 跳过行动。检查点保存已提交 Tick；未执行的墙钟预算不属于游戏世界，读取 / 复位时清空。当前存档仍恢复到守恒业务边界，并不承诺旧版本与新版本逐步轨迹相同。

Harness 的输入分块与内部业务步分离；上限按真实业务步数校验，避免把一个大分块伪装成低成本长跑。审计也固定到每个 10 ms 业务步，因此同初态跨输入分块可以直接比较整段轨迹校验和，以及同一模拟时刻的业务快照。总时长明确要求为 10 ms 的正整数倍，输入分块可以是 137 ms 这类非整步长度；不得静默截短请求。

天气事件与设施风险仍按精确毫秒边界分段积分，固定步只决定居民决策及可见状态何时发布。首个跨过天气边界的业务步最多晚 9 ms 观察到天气，但不会把这 9 ms 错算成另一种天气暴露。

## 后续产品里程碑

1. **时间与终态可信**：本轮修复帧分块问题；后续在驾驶接入时补紧急离岗的安全检查点。
2. **目标点与驾驶**：有限路线、精确路程 / 燃料、实际驾驶岗位；无人驾驶安全停车。宏观进度不移动甲板坐标，不以景物动画反推路程。
3. **停靠有理由**：两个有稳定身份的地点，以水和备件补给、污物清运窗口形成去留取舍；先一条真实车外作业，不同时做贸易、战斗和制造树。
4. **召回并继续**：所有车外人员与任务有 owner；出发前回收人员并按规则处理物资，再完成下一段路。早期单人驾驶 / 采集串行可做技术切片，三人职责竞争通过后才称完整产品里程碑。
5. **可玩与可保存**：保存 / 加载反馈、路线与地点有限库存恢复；用一段短灰盒旅程观察等待、停车原因与下一目标意愿，再决定扩建和蓝图的深度。

厕所实例库存、必要补给、玩家保存、三人接线都是该闭环的交付条件，不需要把整套餐饮、污渍、IK、微活动与完整蓝图系统做完才允许开始旅途。
