# 《游牧工坊》产品愿景与第一版地基

> 状态：**玩法方向草案 v0.15**，更新于 2026-09-08。用户进一步明确“恶劣环境中的温馨移动小家”、从微型车拾荒起步、车内外统一建造、研究场地、3D 打印、简单交易、接力驾驶、路线兴趣点和长期生存张力；当前代码仍是三居民单层 Foundation 样板。本文维护产品目标、范围与取舍；当前已实现行为和近期开发顺序见[Foundation](nomad-workshop-foundation-vertical-slice.md)。

## 1. 当前决策摘要

| 维度 | 当前方向 | 第一版边界 |
|---|---|---|
| 类型 | 小人口、自动居民、连续旅途的移动殖民模拟 | 先证明自动工作、移动家园与车外作业能形成同一循环 |
| 玩家角色 | 玩家化身兼工坊管理者：设定目标、观察、分配优先级和处理危机 | 新起步从 1 名可命名、可选性别与外观的玩家化身开始；首轮仍采用间接指令，不立即改成实时第三人称操作 |
| 人口 | 玩家化身先独自上路，伙伴和更大群体在旅途中加入 | 新起步先验证 1 人 → 前两名伙伴的加入窗口；当前三居民样板继续作为系统回归夹具 |
| 世界 | 逻辑范围很大的种子宏观地图，迷雾探索、区域与稀疏兴趣点；镜头内用地表片段环和远景壳体表现 | 先做一个有限原型路线和少量节点，不先追求大陆级内容、巨型 Terrain 或一比一地形 |
| 移动 | 玩家设定目标点；居民驾驶，车辆以车身长轴为前进轴，以适中速度平稳加减速后持续行驶；主画面车辆方向固定、景物向后流动 | 先做一台长轴清晰的小卡车；目标制、无方向键和局部驾驶寻路；路线应允许连续旅途并保持事件与协作张力 |
| 画面 | 风格化实时 3D，车辆方位不随宏观航向变化；原型允许玩家环绕与缩放镜头 | 优先统一轮廓、材质、光照和镜头可读性，镜头最终限位由试玩决定 |
| 建造 | 小型连续甲板起步，可局部外扩并逐步向上建造；设施保持自由摆放，结构板片采用连接/吸附辅助 | 当前仍为单层；先验证一次非矩形扩建，再做局部两层、梯子和切层；三四层作为后续可配置上限目标 |
| 车外活动 | 停车后居民自动下车采集、建造、修理与救援 | 只做车辆附近的作业范围和一种地面设施 |
| 居民决策 | Utility AI 评估生理压力、岗位、爱好、同伴关系和环境线索，再在高质量候选中有界随机 | 先验证驾驶、做饭、清洁、共同用餐、爱好和轻社交；复杂人格、争执与多人劳动分配随后加入 |
| 生活模拟 | 衣食住行、排泄、家务、爱好和社交都应由可见物质、设施、劳动与后果连接；移动途中也要像一个共同生活的家 | 第一条生活链做“有限食材 → 做饭 → 共同餐桌 → 餐后清洁 / 废弃物”；气泡聊天优先作为可读的事件投影，不先模拟无限对话 |
| 时间 | 居民按 24 小时生活日运作，气候相位独立压缩：一个昼夜约推进一气候周，暂定 48 个昼夜完成一年 | `1x` 下每昼夜约 10–12 分钟只是原型假设；首版先做统一时钟、昼夜与一种天气，不抢跑完整四季内容 |
| 持久化 | 世界记住重要决定，不承诺记住所有偶发细节 | 保存世界种子、主要地点、居民、车辆和重大变化；小事件可消失 |
| 首发平台 | Steam / Windows 付费单机优先 | 先保持输入、UI、存档和业务层可移植，不同时制作移动版 |

一句话产品承诺：

> **照料一群会自己生活和工作的幸存者，把一台濒临报废的荒野工程车逐渐修成家，并在一片会记住重要选择的废土上继续前行。**

2026-09-05 重审时用户选择**先形成一次完整旅程**，该基础工程随后已完成三居民、有限停靠补给、召回再出发与玩家存读档验收。2026-09-06 用户进一步选择先收敛美术与空间成长：起步面积约为大平台参考的四分之一，后续局部扩建、上层甲板、门窗墙顶和天气防护。先完成参考图与实机样板，空间系统按阶段扩展；范围与未验证边界见[可扩建甲板方案](nomad-workshop-expandable-decks-design.md)。

2026-09-08 用户把下一轮体验重心收敛为：从一台很小、长轴明确的普通卡车和一名玩家化身开始，伙伴在旅途中按可控随机加入；车内以做饭、清洁、共同用餐、爱好、看风景和聊天形成温馨日常，危机只在食物短缺、故障、恶劣天气、强盗或难民等少数时刻打破平静。这里的“故事”采用确定性种子 + 权重事件池 + 选择后果，不写死唯一剧本。当前大履带 NW5 保留为后续车架 / 甲板升级形态，不因新起步方案删除。

本轮补充把开局进一步收敛为“先有一辆几乎不能生活的小车，再把废墟里的求生能力一点点搬上车”：玩家化身从一辆只有驾驶位的小汽车开始，在废墟中修好最低行驶能力；车内没有床和活动空间，只能在驾驶位休息，疲劳恢复慢并对健康产生缓慢负担。最初的材料、食物和水靠拾荒获得；任何新设施都先在预定空位上规划，再把木料、金属废料、机械零件等材料逐批搬到占地内，最后由居民在原地完成施工。车内甲板和车外地面使用同一套建造规则，差别只来自支撑能力、承载、天气暴露和是否随车辆移动。随后在旅途中找到并修复一辆废弃小卡车，获得一两个设施的空间，才开始形成“移动小家”；更大的车厢、轮组 / 履带和 NW5 大平台属于后续车辆阶梯。

车辆成长要让玩家感到每一块废铁都改变了选择，但不把游戏变成维修软件。第一轮只保留会改变路线、负载或停靠决策的派生指标：可用承载量、当前载重、动力余量、燃油、蓄电量和一条可解释磨损链。发动机行驶时给电池充电，怠速也能充电但效率更低且继续耗油；轮胎、履带、发动机与发电能力先做少量等级和明确后果，不把螺丝、垫片等拆成几十种资源。资源在地面、居民携带、车上库存和设施之间只有一条可追溯搬运链；车上散落物用有限的箱、捆、油桶和盖布表现，并按容量 / 重量分层，不用装饰物偷偷增加库存。

前两三名伙伴仍由故事窗口约束随机：修车工程师、医生、商人或类似角色各自带来能力、资源或新的选择，但出现时间、具体人物和是否愿意加入由世界 Seed、事件权重、前置和玩家选择共同决定。之后的人口增长更多来自难民或群体事件，玩家从有限候选中选择接纳、交换或放行；事件保留后果和冷却，避免每局都走同一顺序，也避免完全随机破坏平衡。

玩家化身的推荐实现是“可配置的队伍成员 + 管理者视角”：玩家能命名、选性别 / 外观、点选查看和下达意图，但居民仍按现有 `View → Command → Foundation System → Model → ReadModel → View` 自主执行。这样保留项目已经验证的可解释自动生活，同时为以后可选的短时直接操控留下入口；不在本轮把系统改成实时动作生存游戏。

这条主线也服务于另一项已确认目标：用真实游戏开发持续验证、优化 SSFramework 与 AI 自动工作流。每轮围绕一个尚未经历的边界做小实验，将观察、反例、工具 / Skill 改进及未覆盖范围留下；无需急于扩大功能数量。只有调用链与运行证据显示公共摩擦时才演进框架。已完成的旅途、停靠与三居民证据及唯一近期队列统一见 Foundation。

## 2. 产品支柱

### 2.1 移动家园是主角

车辆不是地图切换按钮，也不是一组升级菜单。居民在上面吃饭、睡觉、争吵、工作和疗伤；设施布局、磨损、补丁、纪念品与扩建共同留下历史。行驶时车内模拟继续，停车时它又成为地面作业的能源、仓储和避难中心。

### 2.2 自主但可理解的居民

玩家表达意图，居民自行领取任务。任何未完成的任务都应能解释原因，例如缺材料、道路不通、工具被预留、没有合适工人或当前需要休息。深度来自优先级、人员能力、设施容量和突发压力，不来自反复点选某个人搬一件物品。

### 2.3 旅途是真实过程

世界不是从一个节点直接跳到另一个节点。大地图中的路线持续推进，主画面里的车辆保持稳定朝向，周围景观、地貌和天气向后流动，居民仍会消耗资源、工作和休息。玩家可以中途停车、改道或取消目标，但不用亲自掌握方向盘。连续的是时间、状态与旅程，不要求主画面成为宏观地图的一比一缩影。

### 2.4 每次停靠都在取舍

停车可能是为了补给、维修、贸易、救援、探索、建设或躲避天气。外勤会占用劳动力、时间、食物、装备和安全窗口；离开时还要决定打包设施、遗弃损坏设备，还是把有价值的节点留作长期前哨。

### 2.5 世界记住重要痕迹

建立的前哨、改变的主要地点、帮助或伤害的命名人物、关键资源点与势力关系会保留。尘土、飞鸟、普通路边残骸和没有长期后果的小事件可以重新生成或消失。持久化服务于因果和回忆，不追求保存每一根草。

### 2.6 生活需求必须形成可见因果

“真实”不是给每个对象加一条缓慢下降的数值，而是让玩家看见需求从哪里来、由谁处理、占用什么空间和时间，以及忽视后会发生什么：

- 水储存在水箱或容器中，居民饮用后产生排泄压力；厕所和污物容器有容量，满后必须真实搬运、排放或经管道处理；
- 食物从储藏或冰箱取出，经过制作、进食、剩余和腐败；包装与制作可以产生垃圾，低温只改变腐败速度，不凭空刷新保质期；
- 沙尘天气在可见区域留下污渍或沙堆，触发清理任务并影响设施、卫生或通路，而不是只让一个全局“脏度”数字上涨；
- 设施的老化和维护欠账缓慢积累，污染、超载与振动提高故障风险；真正发生的是可识别的泄漏、卡死或短路，玩家可以检查、保养、准备备件和修理，而不是看一根耐久条归零；
- 睡眠需要床位、时间和相对安全的环境；衣物、保温、洗澡和更复杂卫生只有在气候、疾病或社会反馈能让它们产生选择时再加入；
- 情绪和社交要有可见诱因、恢复行为与后续影响，例如压力高的人主动找可信同伴交谈，而不是装饰性的心情条。

项目采用**选择性真实（selective realism）**：优先模拟会改变玩家决策、居民工作、空间布局、资源物流或故事后果的链条。不能观察、不能交互、不能产生取舍的细节先不模拟。所有新需求都应接回同一套人员、时间、物品、设施、车辆和世界状态，避免变成彼此独立的家务小游戏。

## 3. 玩家职责与核心循环

玩家主要负责：

- 设定目的地、观察路线情报，并在风险变化时改道或停车；
- 规划车辆甲板、设施访问路径、储存和生产配额；
- 设置居民的职业倾向、工作优先级、排班与允许区域；
- 决定谁参加车外作业、哪些资源值得冒险、何时召回；
- 处理贸易、招募、救援、医疗、外交和资源分配；
- 在危机中下达节水、抢修、警戒、撤离等全局命令；
- 决定哪些成果带走，哪些留在世界中形成长期影响。

核心循环：

```text
侦察与获得模糊情报
  → 设定目标点和行驶策略
  → 居民在旅途中生活、生产和维护车辆
  → 因兴趣点、资源、天气或故障决定停车
  → 居民下车采集、建设、修理、救援或防御
  → 打包、遗留、交易或承担损失
  → 带着人员、车辆与世界状态的变化继续前进
```

游戏是连续战役，不按“每二十分钟一关”重置。为了便于游玩和测试，可以让一段路程或一次停靠形成 20–60 分钟的自然章节，并在启程、抵达和重大决定后自动保存。

## 4. 车辆移动：只设目标，车体方向固定

### 4.1 控制语义

玩家在大地图上设置目标点。路线系统根据区域、道路、已知危险和车辆能力估算距离与代价，当前驾驶员执行命令。主画面采用稳定的车辆坐标系，例如左上始终是车头、右下始终是车尾；行驶时地形和景物沿固定方向向右下后退，车辆模型、甲板网格和车内居民不会因宏观航向旋转。

玩家可以：

- 随时取消目标或改设新目标；
- 后期设置普通、节省或紧急等行驶政策；
- 后期标记应避开的危险区域或偏好的道路；
- 在发现事件、故障或资源时下令立即停车；
- 观察预计燃料、时间、磨损和已知风险。

玩家不需要：

- 用方向键持续调整车头；
- 操作油门、刹车或换挡；
- 在居民管理和动作驾驶之间频繁切换身份；
- 因镜头外的一块小石头亲自修正路线；
- 理解主画面与地图北方之间的旋转关系。

第一版只需要“目标点 → 宏观进度推进 → 固定方向的旅途表现 → 可中断 → 到达”的可信闭环，不制作车辆转向动画、局部障碍导航、复杂多点路线、车队编队或动作式避障。重要道路阻塞应成为可读的路线代价、停靠事件或改道决定，而不是让车辆在主画面里绕石头。驾驶仍是一个居民岗位；无人能够驾驶或驾驶员失去行动能力时，车辆会安全停车。后期可通过自动驾驶模块降低岗位占用。下一轮需把车体资产的长轴、驾驶台朝向、环境滚动轴和相机前方统一成一份可测试契约；当前 NW5 的资产轴向仍以 `NW5_AxisForward` 的 `+Z` 为准，视觉宽度偏大是升级车体的表现问题，不先旋转旧路线坐标。

### 4.2 行驶为什么仍然有决策

宏观方向和路线只有在地形影响代价时才有意义。成熟版本中，道路、沙丘、盐碱地、废城、河床和高地应改变速度、燃料、磨损、能见度和遭遇倾向。第一版只选择一种最容易读懂的对比，例如“旧公路更省油但容易遇到阻塞，荒地可绕行但磨损更高”，避免先制作完整地貌系统。

停车不耗燃料，但居民仍消耗食物和水，当地资源也可能枯竭，天气与外部活动会继续变化。因此停留是有效策略，不是无成本暂停世界。

### 4.3 宏观方向与视觉方向解耦

大地图保留逻辑位置、目标、路线长度和区域变化，主画面只表达“车辆正在向前”。玩家向东、西、南或北行驶时，车头在屏幕上的方向都不变；宏观航向通过地图上的路线、罗盘和区域信息表达。

这一取舍意味着主画面不是可测绘的北向地形：

- 道路会被重新投影为大致沿车辆前进方向延伸；
- 进入重要地点时，车辆使用标准化的停靠朝向和入口；
- 路边普通景观不承诺与地图坐标逐物件对应；
- 改变目标不要求车辆在主画面中掉头，只更新宏观路线和后续景观；
- 日照、风向等表现使用“相对车辆”或区域状态，避免制造虚假的北向线索。

这会牺牲少量几何真实感，却显著提升车内可读性、镜头稳定和实现可控性。只要地图明确表达方向，而旅途中的景观、时间和资源变化连续，玩家仍能感到自己正在穿越世界。

### 4.4 旅途与停靠的运行时状态

第一版可以采用一个明确的状态机：

```text
停靠中
  → 召回居民 / 收起设备
  → 准备启程
  → 旅途中（固定景物后移）
  → 接近目标或收到停车命令
  → 减速并准备有限停靠场景
  → 停靠中
```

计划中的主要地点可在接近阶段预加载地点模板，让远景逐渐出现并在标准锚点停车。普通途中停车则冻结景物流动，以当前区域和路线进度创建有限的路边作业空间；可以用沙尘、地形遮挡或镜头缩放掩盖少量拼接，不要求切换成另一张完整世界地图。只有进入“停靠中”后居民才能下车，只有召回完成后车辆才能重新启程。

第一版宏观路线可以只是目标点之间的直线进度，并按经过的简单区域计算代价；不必先实现道路 A*、曲线跟随或全图导航网格。只有路线选择本身已经产生乐趣后，才增加道路偏好、绕行和多段规划。

### 4.5 生活时钟与气候时钟分层

一个可暂停、可加速的模拟时钟负责确定性推进，但居民生理和季节气候使用不同相位：居民仍以 24 小时为一个生活日，气候相位约快七倍，每个完整昼夜前进一“气候周”。暂定每季 12 个生活日、完整气候年 48 个生活日；UI 可以显示“第 2 循环年 · 寒季第 4 周”，不把它伪装成现实公历的某月某日。

`1x` 下一个生活日先按 10–12 分钟试做，因此一次 20–30 分钟旅途约跨 2–3 个昼夜，一季约 2–2.4 小时，完整气候年约 8–9.6 小时。居民在这段时间内真实经历数次睡眠、进食和工作；胡须、饥饿造成的体能亏空、疾病与恢复按生活日推进，不因气候日历快七倍而加速。季节温度、日照和天气倾向连续过渡，不在换季瞬间切换整套场景。

这些数值的目标是让旅途、停靠和四季都能在一局内被体验，不是追求现实比例。首版只建立统一时钟、昼夜和一类沙尘压力；只有长跑与试玩证明节奏成立，才增加完整四季、作物生长或季节资源。若频繁睡眠打断观察、夜晚过长或一年显得像快速换皮，应先调整昼夜墙钟时长、夜间表现占比和气候相位倍率，而不是修改人体需求去迁就日历。

### 4.6 平稳连续旅途与动态张力

用户希望车辆氛围像移动中的客厅，但不希望玩法变成缓慢的观光动画。下一轮的目标是“平稳而不拖沓”：车辆采用适中的巡航速度和独立的加速 / 减速曲线，减少无意义的启停；接近路线兴趣点、响应停车命令或发生真正危机时提前刹车。非关键需求不打断驾驶员，普通居民可以在行驶中研究、休息、娱乐和交谈；只有安全边界、驾驶员无法继续或明确危机才停车。第一轮不追求机械仿真，先用纯 C# 运动策略保证跨帧、暂停、读档和不同输入分块一致。

镜头继续保持可环绕的俯瞰管理视角，但焦点、距离和旋转增加克制的缓冲；缓冲只影响表现，不改变鼠标选取、导航或业务时间。验收不只看车速，还要看单位旅途时间内是否有可理解的观察、规划或协作决定；起步 / 刹车不突然，长段行驶不空洞，暂停后状态不漂移，恢复和读档不瞬移。若信息密度不足，优先增加路线兴趣点、成员活动和资源取舍，不单纯把车开得更慢。

### 4.7 开局车辆、统一建造与载荷成长

开局车辆按“能动起来”而不是“已经拥有完整基地”设计。三个阶段先形成一个可读的成长阶梯：

| 阶段 | 车辆与空间 | 生活限制 | 玩家要解决的问题 |
|---|---|---|---|
| 微型车 | 只有驾驶位，零车载设施，几乎没有有效储物面 | 驾驶位休息恢复慢，健康缓慢受损；不能在车上制作 | 先修好最低行驶能力，找到水、食物和可带走的废料 |
| 废弃小卡车 | 可修复的车厢，容纳一两个基础设施与有限货物 | 仍然拥挤，床、储物、研究台和供水 / 厨房要竞争空间 | 选择先建床、储物、研究台还是供水 / 厨房，并承担载重变化 |
| 扩展车架 / NW5 | 可扩建甲板、较高承载和多种设施；NW5 大履带是后续形态 | 维护、燃料、电力和结构复杂度增加 | 用更高承载换取更长旅途、更多成员和更安全的生活链 |

第一条生产边界不是工作台，而是“蓝图占地 + 材料暂存 + 原地施工”：设施先占据规划空位，材料到齐后由居民在工作姿态上逐步建造；拆除时先停止使用、清空正在处理的资源，再按回收规则生成可搬运的材料批次。只有搬运完成，材料才随车离开。第一轮材料保持粗粒度：木料、金属废料、机械零件、燃料、食物、水、药品和电量；更细的紧固件只有在实际决策被证明需要时才增加。

车辆性能先用整数化的“质量 / 功率 / 电量 / 磨损单位”在模拟层表达，表现层再把它投影为轮胎下沉、发动机声音、蓄电池指示和车厢堆放。行驶、怠速和设施负载共同消耗燃油或电量；超载、轮胎磨损、履带承重和发动机余量只在确实改变速度、故障概率或可走路线时进入规则。这样既能支持“轮子需要更多、更大，履带更能承重”的玩法，又不会为尚未影响选择的每个机械零件建立独立系统。

### 4.8 统一建造、研究场地与地点生命周期

车内和车外不再有两套建造系统。玩家先在可达、可承载的空位上规划设施占地；蓝图占用 3×2 等实际空间后，居民把木料、金属废料、机械零件等材料搬到蓝图的施工暂存区，材料堆会真实占用该区域，随后居民在原地按工作量逐步建造，完成后才原子启用设施。取消、支撑失效或启程都会经过明确的材料回收 / 遗留规则，不把完成设施瞬间变成菜单图标。

研究台（可以是书桌）不是建造前置，而是研究能力的可选场地：居民没有书桌时，可以坐空地、凳子或躺在床上研究；书桌上的纸、笔、水杯等通过已有 `PlacementRegion` 放置规则表现，并提供研究速度、并行人数或复杂研究资格加成。只有确实需要稳定工具、资料和姿态的复杂研究才要求书桌；普通生存和基础设施不应被研究台卡死。

地面设施按地点分成四种可观察状态：

| 状态 | 规则 | 离开后的结果 |
|---|---|---|
| 车辆设施 | 建在车辆甲板上，遵守 `VehicleDeck` 的占地、承载和通路；库存与设施随车移动 | 随车辆移动，不需要拆解；车辆升级或拆除时走正常建造 / 回收事务 |
| 节点永久设施 | 建在有稳定 `NodeId` 的废墟、驿站或前哨地面；设施、库存、磨损和升级写入节点状态 | 永久保留，可回访继续使用；地图显示节点设施 |
| 途中临时设施 | 建在没有稳定节点身份的路边停靠场景；绑定路线 id、锚点进度和可配置保留距离 | 车辆仍在保留距离内时可回去取用；超过距离后进入失效状态并从世界清理 |
| 已远离失效 | 玩家选择把设施留在荒野，且车辆已驶过保留距离 | 设施和未搬走的普通材料不再传送到车上，也不产生隐藏回收；需要下次重新建造或拾荒 |

出发前用一条温和的检查提示告知玩家：“这里的设施属于节点 / 路边临时点；拆除可以按回收规则带走材料，留在节点会永久保留，留在荒野会在远离后失效。”玩家可以取消启程继续处理，不用被强制弹窗打断。第一版只做一个永久起步节点和一个途中临时场景，保留距离先做成可调参数，不提前承诺完整前哨网络。

相应的科技树不是堆叠几十个配方，而是按能力解锁：

| 层级 | 解锁内容 | 依赖 |
|---|---|---|
| T0 · 拾荒 | 搜索、携带、饮水、进食、燃料和有限资源堆 | 无；只能维持生存，不能普通建造 |
| T1 · 基础建造 | 修理车辆、储物箱、简易床位、供水或简易厨房模块；所有施工都在目标空位完成 | 起步废墟材料、可达支撑面 |
| T2 · 研究场地 | 书桌提高普通研究效率，并解锁少量复杂研究；纸、笔、水杯等可放置物成为可见准备 | 基础研究内容；复杂项目要求书桌 |
| T3 · 车辆成长 | 发动机 / 蓄电池 / 轮组或履带模块、车厢扩展 | 小卡车、机械零件、承载和动力条件 |
| T4 · 移动工坊 | 局部扩建、多层连接、更大生产链和更可靠的车外施工条件 | 稳定材料来源与安全的节点 / 路线 |

伙伴、阵营、难民和地图能力是事件与世界层解锁，不能只靠“科技点”凭空购买。每次解锁都要增加一个可见的生存选择或生活链，若只增加菜单选项就暂缓。

### 4.9 3D 打印、稀有零件与简单交易

3D 打印机是把拾荒材料转成精密设施零件的技术门槛，不是万能生产机。最简单的打印机也需要不可打印的控制芯片、打印介质和电力；芯片不能由打印机自我复制，必须从废墟、特殊残骸或商人手里获得。推荐的首个打印机来源是找到一台损坏设备并修复，或直接从稀有商人处购入；不允许玩家用普通废料从零徒手制造第一台打印机，避免科技树递归锁死。

基础床位、储物箱、简易供水等设施可以由粗粒度材料直接建造；厨房控制器、发动机控制模块、精密过滤器等复杂设施才要求打印件。打印件按少量功能类别管理，例如结构件、壳体件、精密连接件和控制件，不为每个螺丝创建资源。打印过程消耗 `PrintFeedstock` 和电量，耗时可被居民照料但不能凭空提高产量；打印机损坏或缺芯片时，已有设施仍可使用，只是无法继续制造新模块。

交易首版采用一种简单的交换媒介，例如“商票 / 交换券”，不同时做多货币、动态市场、议价和派系经济。商人在路线节点或少量可预告的路边地点搭起有遮棚的桌台，桌面、箱子和货堆直接读取真实库存；交易窗口只显示有限买入 / 卖出槽位、价格、库存和玩家当前物品。商人库存由世界 Seed、商人身份和补给周期确定，芯片等稀有物品数量少、刷新慢且价格高，交易结果写入存档，避免重复刷取。后续若试玩证明以物易物更符合世界观，再在这层薄交易服务上增加替代支付，不先建第二套经济系统。

### 4.10 接力驾驶与连续岗位

驾驶仍由独占驾驶租约拥有，但驾驶员可以在疲劳进入危险线前发起“请求接班”。符合条件且已经在车上的居民以普通行动意愿接受请求，走到驾驶位；当前驾驶员在交接完成前保持原速度和驾驶租约，交接提交时一次性转移租约，不减速、不停车、不出现两个驾驶员。请求、候选接受、前往驾驶位和原子交接都应成为可读的居民行为。

接班人必须健康、清醒、未被更高优先级任务占用，并具备驾驶资格；没有人愿意接班时，当前驾驶员可以继续驾驶到安全阈值，之后才执行普通安全停车。接力不是取消疲劳规则，而是把强制停车提前转化成团队协商和岗位安排；玩家可以提高驾驶优先级，但不必逐帧手动控制。

### 4.11 温馨氛围与长期生存张力

休息、研究、娱乐和爱好采用软压力曲线：短时间缺少不会立刻造成失败，持续缺少会降低工作效率、研究速度、健康、心情或协作意愿，越接近危险线后果增长越快。这样车内可以有较多温馨日常，但玩家仍需安排床位、研究时段、接班顺序和资源余量。

旅途中的活动按三层处理：

1. **背景活动**：阅读、画画、聊天、看风景、轻度研究，可在移动中进行；
2. **需要准备的活动**：做饭、复杂研究、维护和打印，需要设施、材料、电力或成员协作，但不一定立即停车；
3. **硬性危机**：缺水缺粮、驾驶员无人接班、动力故障、恶劣天气或敌对事件，才改变路线或强制停车。

这使“舒缓”成为内容与镜头的气质，而不是降低所有数值压力。气泡、音效和动作表现日常亲密，资源、岗位和路线后果继续提供玩法张力。

## 5. 双尺度世界：宏观地图与固定旅途舞台

### 5.1 四层精度

| 层级 | 内容 | 模拟方式 |
|---|---|---|
| 宏观地图 | 区域、道路、气候、污染、势力、主要地点、逻辑位置与迷雾 | 记录路线和进度；坐标只服务距离与规则，不要求对应 Unity 世界米制空间 |
| 旅途舞台 | 固定朝向的车辆、向后流动的地表、景观、天气和远处地标 | 根据当前区域与路线进度拼接或复用表现片段，不承担宏观寻路 |
| 当前停靠场景 | 车辆附近可活动地面、资源、设施、事件与车外居民 | 停车时生成一个有限作业空间，在离开前精确模拟 |
| 远方世界 | 商队、风暴、势力变化、前哨产出 | 使用聚合状态和经过时间推进，不保留完整 GameObject 或居民 AI |

世界种子决定宏观区域、道路、主要地点和路线条件；旅途舞台根据“区域 + 路线类型 + 进度 + 天气”选择景观材料；停靠场景使用有身份的地点模板或临时场景 Seed。程序系统决定“在哪里和何时”，设计内容保证“发生什么以及为什么有趣”。

第一版只验证：同一 Seed 能重建同一宏观地图和主要地点，路线进度能驱动连续旅途表现，当前停靠点能够保存恢复，主要地点离开再返回时重要状态不会丢失。它不需要先生成完整大陆或连续地形。

### 5.2 选择性持久化

| 状态等级 | 示例 | 保存策略 |
|---|---|---|
| 重大永久状态 | 前哨、主要地点是否修复或搜空、命名人物去向、剧情与势力决定 | 永久记录稳定 ID 和结果 |
| 区域聚合状态 | 已探索范围、主要资源丰度、危险度、最近到访时间 | 记录少量区域数据，不保存每个物件 |
| 当前临时停靠点 | 玩家正在其中存档的普通路边作业场景 | 离开前随存档保存；离开后默认丢弃 |
| 可重建内容 | 宏观区域、道路、主要地点身份、旅途景观材料 | 由世界 Seed、路线与地点模板重建 |
| 短期或偶发内容 | 尘土、动物、普通残骸、路过商人、小型随机事件 | 通常不保存；必要时只加已消费标记或短期冷却，避免重复获利 |

普通荒野中的一棵装饰树不必获得永久存档记录。若玩家在临时停靠点建设信标、重要设施或正式前哨，该地点才被“提升”为具有稳定 ID 的持久地点；若某处资源是否采空会改变路线和未来选择，也应保存聚合资源状态或关键物件，而不是逐树保存。

### 5.3 大地表的表现与路线可达性

地表可以做到“逻辑上很大、镜头内没有边缘”，但不建议制作一张无限延伸的 Unity Terrain。当前旅途舞台已经按路线进度让地表沿车辆坐标滚动；后续应把它扩展为车辆周围的地表片段环、远景地貌层和稳定的地平线背景。近景片段循环复用，中景用路线区域和地标变化，远景用地平线壳体、雾气、沙尘和大气衰减遮蔽拼接。雾尘是过渡和氛围手段，不能单独用来掩盖近处的地表断边。

相机允许拉平时，远裁剪面内始终应有地平线代理或远景壳体；车辆周围的可行驶地面由对象池循环提供，不让玩家看到世界坐标的外边界。这样既能支持很长的路线，也避免巨型 Terrain 的内存、精度、烘焙和存档负担。真正需要永久身份的是路线、节点、事件和资源聚合状态，不是每一块远景地表。

由于车辆当前不能拐弯，所有可交互兴趣点都必须挂在路线锚点上：难民、资源点、商人摊位、奇特建筑和重要景观都有路线进度、出现窗口、停车锚点和回收规则。路线两侧可以有看得见但不可交互的装饰景物；如果一个对象能被玩家调查、救援、交易或采集，它必须在车辆可达的路线段上，不能让玩家看到“就在旁边却永远到不了”的可玩目标。未来真正加入转向或支线时，再扩展为带分叉的路线图。

### 5.4 由此删除的实现复杂度

双尺度模型让第一版可以明确不做：

- 覆盖整张大陆的 Unity Terrain 或等价连续地形；
- 与宏观坐标一比一对应的地形区块、NavMesh 和物件状态；
- 车辆模型在世界中长距离平移、旋转和浮点原点回正；
- 车辆为了避开每个可见障碍进行局部路径规划；
- 不同宏观航向下旋转甲板、镜头、UI 和车内寻路；
- 为返回普通路段保存所有景物与玩家小改动。

旅途表现可以使用对象池复用短地表片段、植被、残骸和远景层；宏观路线只推进逻辑距离并采样区域规则；停车时才加载或生成有限作业场景。若未来视觉原型证明这种复用产生明显“跑步机感”，先增加景观语法、地标和过渡变化，而不是立即退回一比一开放世界。

## 6. 建造与镜头：从小甲板成长为分层移动工坊

### 6.1 单层基线与多层成长

多层甲板会同时放大：

- 居民寻路、拥堵、楼梯和任务预留的复杂度；
- 屋顶、楼板和上层设施的遮挡；
- 选择物件、框选区域和理解故障原因的成本；
- 镜头旋转、楼层切换、提示图标和车外观察的 UI 负担；
- 车辆扩建、损伤表现和自动化测试的状态空间。

此前因此选择单层作为旅途地基。用户现已明确希望通过局部上层增加成长和空间规划，旧“禁止第二层”不再是长期产品约束；上述成本转为分阶段验收项目。先保留同层连续几何与导航，在局部第二层验证梯子、支撑、携物、切层和存档后，再决定三四层的常规上限。

规则采用分层平面加显式跨层连接，视觉完全为实时 3D。楼层可只有局部甲板；真实支撑、开口和可达施工位要成立。具体建议见[可扩建甲板、多层建造与表现衔接](nomad-workshop-expandable-decks-design.md)。

### 6.2 面积、承载与生活空间共同成长

容量不只依赖无限扩大地板：

1. **渐进甲板扩建**：起步面积约为大平台概念图的四分之一，允许增加小板形成非矩形；轮组跟随主车架挂点，大面积或多层需要提升承载和车架等级。
2. **边缘和专用挂点**：太阳能板、储罐、天线、灯、炮塔、冷凝器等可以安装在甲板边缘或非行走挂点。
3. **设施升级与多用途空间**：高级厨房不只是数值更高，也可减少人力或兼作社交空间；观景区同时服务侦察和减压。
4. **车外临时产能**：重型抽水、拆解、采矿和大型防御主要在停车后部署，不把所有工业都塞进车内。
5. **明确人口上限**：成熟游戏常驻约 8–12 人，不为容纳数十人把车辆扩大成难以阅读的城市。

首次扩建仍只验证一次受控外挑和真实材料投入。之后逐步加入局部上层、梯子、墙、门窗与顶棚；围护通过遮雨、防尘和生活空间产生用途。具体尺寸、外挑限制、层高和运输方式由布局与玩法证据校准。

### 6.3 镜头随任务和规模变化

- 车内管理时，车辆可占画面约 60%–70%；
- 行驶观察时镜头稍微拉高，车辆约占 35%–50%；
- 车外作业时允许在有限半径内平移和缩放；
- 底盘扩建后调整镜头包围盒和最小缩放，但设置最终上限，不能让居民缩成无法辨认的小点。

车辆在旅途舞台中保持固定局部朝向，默认观察角度左上为车头、右下为车尾；这不再意味着禁止玩家观察其他侧面。当前 Foundation 已支持中键环绕、滚轮缩放和对应双指手势，作为本轮原型基线保留。宏观路线改向不主动旋转车辆或镜头，景物流动依据车辆坐标计算。正式版本是否进一步收紧镜头角度，由遮挡、居民辨认和设施操作的试玩证据决定。车辆内部可采用自动隐藏屋顶、剖面或开放甲板表现。

### 6.4 实时 3D 与复用优先的资产策略

游戏采用 Unity 中直接渲染的 3D 模型、材质、灯光、VFX 和骨骼动画，不先把 3D 预渲染成 2D 精灵。高位俯瞰、分层显示和有限人口控制观察与操作成本。固定设施由 Blender 分件制作，可变楼板、梁和墙段使用同规格模块/参数化生成，逻辑几何与可见模型分别由同一构件定义派生。

复用不等于让所有内容看起来相同。资产投入按镜头价值分层：

1. **英雄层**：车辆总体轮廓、代表性居民、关键设施和核心交互需要人工审美与接触点精修；
2. **模块层**：墙板、管线、储物、研究台、衣服、头发、工具和环境组件共享尺寸、材质与组合规范；
3. **背景层**：远景、路面片段、普通残骸和植被优先对象池、程序组合、材质变体与低成本动画。

居民默认共用一套标准 Humanoid 骨架、Avatar 和通用动作库，通过头部、发型、衣服、背包、配色、工具、体型允许范围与动画节奏形成差异。设施不为每个型号制作一套完整人物动画，而是声明可复用的交互契约，例如站位、朝向、动作类型、手部目标、工具挂点与 VFX / SFX 锚点；必要时再用 IK 或少量专用动画修正英雄级交互。

Foundation Prototype 的首个 3D 管线证据限制为：一套标准骨架、一种基础身体比例、三名模块化外观居民、不超过约八个通用动作，以及三至四类设施交互锚点。首版不做面部绑定、口型、布料模拟、逐指动画、多套不兼容骨架或每台设备专属的完整动作集。可接受风格化简化，但不能接受明显脚底滑动、手穿过工具、轮廓混乱、比例失控或同一镜头中的材质风格割裂。

### 6.5 水的模拟与表现分离

游戏规则持有水量、容量、水质、处理吞吐、泄漏和损耗等真值；渲染层只读取这些数据表现液位、颜色和事件，不能通过粒子数量或水面高度反向结算资源。第一版不做网格流体、逐格液体压力、复杂热力学或海洋模拟。

水的视觉表现按用途分三类：

1. **容器内液体**：用简单液面 Mesh 或材质参数跟随容器填充率，不模拟真实体积流动；
2. **积水、水池与室外小水面**：共用 URP Shader Graph 或少量自定义 HLSL，以滚动法线、深浅颜色、接触边缘和泡沫建立读感；PC 高画质可为少数重要水面增加屏幕折射或平面反射，基础与移动档关闭这些高成本特性；
3. **泄漏、滴水、蒸汽与飞溅**：由 Particle System 或 VFX Graph 响应模拟事件，只做短时反馈，不拥有水量真值。

基础画质优先半透明或近似不透明水材质、Reflection Probe 和受控高光，保证固定斜俯视镜头下清楚、稳定且可批处理。若未来迁移 HDRP，可为材质增加 HDRP Adapter，并按代表性镜头评估其 Water System；水循环模拟接口不随渲染管线改变。该方案仍是待灰盒验证的技术方向，在水 / 排泄玩法链和镜头需求成立前，不先投入完整水体 Shader。

## 7. 居民决策与设施深度的分期

### 7.1 决策原则：有界随机的 Utility AI

居民的“下一步做什么”使用 Utility AI（效用 AI）而不是固定脚本，也不把所有正权重候选直接放进一次原始轮盘赌。随机性应该从多个合理选择中产生自然差异，不能让角色在脱水、火灾或关键故障面前因为一次低概率抽签去画画。

一次决策采用以下管线：

```text
需求 / 工作单 / 安全 / 休闲产生行动意图
  → 展开目标、交互位、容器和前置动作，组成完整行动方案
  → 过滤不可达、无资源、缺少兼容容器、未获许可或已被预留的候选
  → 按完整路径与步骤评估预期收益、紧急度、个人倾向、耗时和风险
  → 按意图归并，避免“十把椅子”让休息概率凭数量放大
  → 按“不处理的后果”进入日常 / 紧迫 / 严重 / 危急四级风险仲裁
  → 在当前最高可执行风险层内，保留紧迫度相近且效用合理的少量候选
  → 使用带温度的加权随机选择
  → 原子预留目标并执行；完成、失效或重要事件发生时再决策
```

每个候选行动的效用来自“行动完成后预计减少多少压力、改善多少世界状态”，而不是只给动作写一个固定权重。概念上可以表示为：

```text
效用 = 各需求的预期压力下降
     + 工作紧急度、玩家优先级、解锁后续任务的价值
     + 居民技能、职业倾向、性格偏好、任务等待时间与继续当前工作的奖励
     - 路程、耗时、资源、风险、切换工作与重复行为的代价
```

需求使用可配置的非线性压力曲线：每项需求分别声明开始响应点、紧急点和曲线形状，轻微饥饿只提供很小驱动力，接近危险时快速上升；曲线接缝保持平滑，不用突然跳变的硬阈值伪装优先级。评估行动时把执行期间仍会发生的口渴、疲劳等变化算入预计结果。因此一顿同时恢复饥饿、少量口渴和疲劳的饭，会按三项状态在行动前后实际减少的压力共同得分；若居民并不口渴，就不会凭空获得这一部分效用。维修、人力发电等工作则按故障后果、资源缺口、依赖任务、玩家政策和预计产出计分。

原始轮盘赌会让低分选项始终保留不合理概率，也会因同类设施数量增加而扭曲选择。推荐先保留 Top-K 或达到最高分一定比例的候选，再进行 Softmax 式轮盘选择：

```text
P(a) = exp((U(a) - Umax) / T) / Σ exp((U(i) - Umax) / T)
```

温度 `T` 越低越接近选择最高分，越高越有变化。风险层不是“火灾永远大于如厕”的动作名排序，而是当前情境下的动态后果：可隔离的小故障可能只是严重，即将引发死亡或车辆毁灭才是危急。先排除不可执行方案，再只在最高可执行风险层中仲裁；同层紧迫度超出容差时先处理更迫近的后果，容差内才比较完整行动效用。危急层默认确定性选择；紧迫 / 严重层只保留很低温度；普通工作保持适度稳定；休闲和多个近似等价的低风险选择可以更随机。具体分层、容差与温度都是可调假设，不写成不可反思的永久规则。

这一结构能用同一套规则处理极端冲突：“卫生间起火 + 膀胱已满 + 重病”不是把三个巨大权重相加，而是先生成逃生、报警 / 灭火、去其他厕所、原地缓解或求援等具体方案。可执行的危急安全方案会压过紧迫生理需求；若火场方案因无能力、无通路或无工具而硬阻塞，它会保留为可解释诊断，但不会让居民在原地冻结；选择器继续执行下一个最高可行层的“最小伤害”方案。多名居民时还需要独立的事件任务分配与抢占协议，不让每个人都各自冲向同一处火点。

角色选择行动后应获得最短承诺时间、当前行动加成和切换成本，避免每次数值波动就来回走动；通常只在行动完成、目标失效、设施被占、出现明显更高等级的紧急情况或定期低频复评时才切换。每个主行动都声明原子、检查点可中断或可补偿的中断契约；伸懒腰、调整姿势等无需导航和硬预留的微活动可叠加表现，需要离开工位的喝水 / 如厕则是检查点挂起的绕行子计划，不能伪装成“无成本小动作”。等待过久的工作获得缓慢增长的老化加成，防止普通任务永远得不到处理；任务选择时必须原子预留目标、材料与交互位，预留失败则重新决策。

成熟版本可以让性格改变需求曲线、偏好与随机温度，例如有人更愿意作画，有人通过独处看风景减压，也有人在高压下更容易僵住或寻求同伴。但有意设计的非理性压力反应必须成为可见状态和可理解后果，不能用隐藏的随机失误冒充性格。

随机数使用可保存或可派生的确定性 Seed，例如世界 Seed、居民稳定 ID 和决策序号的组合。开发视图应记录候选、排除原因、各分项得分、最终概率、随机结果与中断原因；玩家界面只需表达主要动机和阻塞，例如“严重口渴，先去饮水”或“维修台缺少零件”。这样既能自动长跑复现问题，也不会把角色变成需要阅读公式的表格。

随机性不只用于“选哪个行动”，也可以让摄入量、动作阶段输出率、污渍和故障产生有因果的个体差异，但样本应在事件开始时一次确定并进入存档，不能每帧重新随机。水、食物、排泄物、温度和进度采用带量纲的定点连续量；杯盘、零件、床位和交互位仍是有身份的离散对象。居民只模拟对玩法有直接杠杆的小时到数日变化：昼夜节律与睡眠债、短期饥渴、连续营养不足造成的体能亏空、疾病与恢复，以及胡须等分级外观变化；不加入月经、固定月度能力波动或其他长期人体节律。完整边界与迁移顺序见[狭小空间生活仿真设计](nomad-workshop-domestic-life-simulation.md)。

Utility AI 只决定“现在做什么”；移动、预留、交互、进度和失败恢复由可复用的行动执行器负责，3D Animator 只呈现结果，不拥有资源结算或任务完成真值。居民 AI、游戏规则与 Unity 表现保持这一接缝，才能复用同一套搬运、维修、休息和设施交互而不把逻辑绑死在动画事件上。

具体目标不能各自发明权重公式。候选生成层应先把“取得合适容器 → 必要时洗手 → 走到来源 → 取货 → 走到目标 → 使用 / 收尾”展开成步骤，再用命名分项折算。硬可行性与软偏好分开：没有防漏容器时不能搬水属于硬阻塞；厕所较远或较脏属于耗时、卫生和风险成本。紧急需求提高延误成本，因此低压力时可以绕路选择更洁净的设施，高压力时会更看重就近可用。车辆晕车同样作为居民状态修正高强度工作成本与休息收益，不作为散落在每类任务中的特殊分支。

### 7.2 内容分期

成熟方向保留饮水、食物、睡眠、排泄、卫生、健康、舒适、性格、爱好、关系和压力反应，但第一版不能同时展开所有细节。

第一版居民只需要：

- 3 名有名字、技能侧重不同的居民；
- 饮水、营养、疲劳、排泄四项生理压力，健康作为严重失衡、环境与疾病造成的结果状态；当前 Foundation 已先接入严重缺水→健康损害→死亡的最小闭环；
- 建造、搬运、维修、驾驶和车外采集等工作类型；
- 全局优先级、个人职业倾向、有界随机的效用选择和任务预留；
- 清楚显示当前行动、下一任务和无法工作的原因；
- 至少一条真实生活物质链：从有容量的来源取水 / 食物，经使用产生污物或垃圾，再进入有容量的目的地；
- 停车后下车、出发前召回和失去行动能力的安全语义。

当前压力与首个爱好已能产生可观察恢复。先验证三人在旅途、补给与照料中的岗位取舍，再决定是否用一次交谈验证社交恢复。洗澡、衣物、复杂卫生、长期关系、个性化压力反应、复杂排班和创伤继续延后。首版可以保留自然的数据扩展点，但不创建空 UI、占位数值或尚无行为后果的“形式化系统”。

### 7.3 生活模拟按垂直因果链推进

为了避免一口气建设“人体模拟器”，生活能力按下列实验顺序逐步加入；每一步都必须在真实镜头中有动作、物品、设施和后果：

1. **水与排泄**：居民从实际容器取水，饮用降低口渴并逐渐产生排泄压力；厕所占用、容量、污物容器和人工清运成立。
2. **食物与垃圾**：从储藏 / 冰箱取食材，制作并进食，剩余可放回；温度影响腐败，制作或消费产生少量垃圾。
3. **人工物流与自动化**：先由居民搬运水桶、污物桶和垃圾；稳定后再比较管道自动供水 / 排污，断电、堵塞或破损时退回人工方式。自动化减少劳动，不删除物质与容量。
4. **环境污渍、维护与故障**：沙尘暴让有限表面 / 区域缓慢积尘，居民使用工具清理；同一环境提高设施维护欠账和老化速度，最终可能触发可预警、可复现的泄漏 / 卡死等具体故障。
5. **简单压力与社交**：压力由拥挤、疾病、危险、孤独或连续工作产生；先用交谈、独处看远方等一两种恢复方式验证角色感，再决定性格和关系深度。

这些是生活专题内部的因果依赖，不是全项目的开发队列。当前水链、身心状态和首条维修已经接入；下一步生活工作只优先解决旅途中的供给、容量与恢复出口，食物细化、清洁工具和社交按试玩需要再展开。前一步若只增加琐事、没有产生有趣的空间或人员取舍，应先修改或删除。

底层可以复用少量“有界标量 + 速率修正 + 阈值事件”的数学原语，但语义类型保持分开：设施耐久、食物新鲜、居民疲劳与区域清洁不能因为数值范围相似就共用一个万能 `DurabilityComponent`。只有需要影响决策的对象才持续模拟；大量背景道具保持静态。

设施状态进一步区分缓慢且通常不可由普通修理清零的等效磨损、可通过保养改善的维护欠账，以及已经发生的具体损伤 / 故障。故障使用随时间积分的风险率与预先保存的随机阈值，而不是每帧掷固定概率；触发时才取样模式和严重度。这样暂停、加速、帧率与存档读取不会改变同一世界的事故轨迹，玩家也能通过清洁、检查、保养和更换部件主动改变风险。

饮水站本地库存、例行补货与紧急补水的分流，以及进食地点、餐具、剩饭、表面空间、污染和后续温度 / 电力 / 管道的落地边界，见[狭小空间生活仿真设计](nomad-workshop-domestic-life-simulation.md)。这些细节用于制造选择和角色依恋，不以增加家务点击量为目标。

## 8. 第一版：Foundation Prototype v0.1

本节保留单层旅途地基的阶段范围。2026-09-06 新确认的局部扩建、多层与围护接续在该基线上，按 Foundation 近期队列推进；此处单层边界不再代表长期产品上限。

### 8.1 目标

第一版不是商业垂直切片，也不是内容 Demo。它只回答一个产品问题：

> **看着三名居民自动修复、经营并驾驶一辆移动工坊，再在途中停车完成车外作业，这一整段过程是否清楚、有选择、让人想继续照料他们？**

目标体验长度约 30–45 分钟，可以使用灰盒与临时音画。只要核心反馈不成立，就修改循环，不通过增加生物群系、人物和事件掩盖问题。

### 8.2 可玩路径

```text
一名玩家化身从废墟里找到一辆只有驾驶位的小汽车
  → 修好最低行驶能力，拾荒获取水、食物、燃料和粗粒度材料
  → 在可达空地规划第一座基础设施，把材料逐批搬到占地内并原地施工
  → 在离开前拆除或保留地面设施，按节点 / 路边生命周期处理未搬走的材料
  → 途中找到并修复一辆废弃小卡车，选择第一两个车载设施
  → 在路线节点遇到商人摊位或损坏的 3D 打印机，决定用资源换取稀有芯片、打印介质或其他关键物品
  → 设置目标点，车辆平稳起步，居民在持续旅途中休息、交谈和观察环境
  → 因资源、天气或故障在合适时机减速停车，生成有限路边作业空间
  → 遇到一名有能力和动机的伙伴，按事件后果决定是否同行
  → 重新整理载荷、设施和路线，带着可追溯的选择继续前进
```

### 8.3 内容上限

| 内容 | v0.1 上限 |
|---|---|
| 世界 | 1 个逻辑范围很大的宏观原型区域、1 种主要地貌、旧公路与荒地两种路线代价、约 3 个有身份的路线节点、1 类临时停靠场景；可交互兴趣点全部绑定路线锚点 |
| 移动 | 目标点、路线进度、固定车体朝向、平稳加减速、接力驾驶、景物后移、停车 / 取消和基础燃料消耗；不做手动驾驶、车体转向和局部避障 |
| 车辆 | 1 辆只能休息在驾驶位的微型车、1 辆可修复的小卡车、有限车载设施、粗粒度载荷 / 燃料 / 电量 / 磨损，以及 1 条“老化 / 保养 → 具体故障 → 修理”链；NW5 为后续升级形态 |
| 居民 | 1 名可命名玩家化身起步，前两三名伙伴在受约束的随机故事窗口中加入；饮水 / 营养 / 疲劳 / 排泄四项生理压力与健康后果、约 5 类工作、有界随机 Utility AI、任务预留、选择依据与阻塞原因 |

| 资源 | 木料、金属废料、机械零件、芯片、打印介质、交易券、燃料、水、食物、药品、电量，以及污物 / 垃圾两类生活输出；全部经真实库存转移，不先做螺丝级材料或几十种品质 |
| 车载设施 | 微型车无固定设施；小卡车先容纳一两个基础设施，后续再加入储存、供水、床位、研究台、3D 打印机、厕所或污物容器等约 6–8 类有效设施；若范围超限，先减少地点内容，不把生活链退化成抽象按钮 |
| 制造与交易 | 1 台可修复或购入的基础 3D 打印机、少量打印件类别、1 种交易媒介、1 类商人摊位和有限商品槽位；不做动态市场、议价和多货币 |

| 地图与存档 | 世界 Seed、迷雾、当前路线进度、临时停靠点、车辆、居民、主要地点与重大选择；离开后不保存偶发小事件 |
| 产品外壳 | 开始、暂停、1×/加速、保存/读取、返回标题；开发 UI 可先于正式美术 |

### 8.4 必须先做对的地基

- **模拟时钟**：暂停、加速、需求与作业使用统一时间语义；表现帧率不直接决定经济结果。
- **双时间相位**：生活日驱动居民因果，压缩气候年驱动季节；两个相位都由同一模拟时刻推导，不能把需求倍率和换季倍率混成一个全局加速。
- **稳定世界身份**：世界、主要地点、当前路线、居民、设施和任务拥有可存档的稳定 ID；旅途装饰片段不获得永久身份。
- **效用决策与执行分离**：候选生成、效用评分、有界随机、任务预留和行动执行各自可观察；动画只呈现结果，不负责经济结算。
- **任务与预留**：居民不会重复领取同一物资或互相等待；失败原因可查询。
- **真实库存与搬运**：每个搬运任务都包含来源、目的地、物品、数量和原因；原子预留来源数量、目的容量与交互位。不存在没有来源 / 目的地的抽象“整理货物”工作。
- **生活因果链**：摄入、消耗、排泄、垃圾、腐败、污物和清理满足明确输入—输出与容量边界；管道只是自动运输接缝，不能让资源凭空出现或消失。
- **污渍是可见对象或区域**：沙尘与垃圾生成有限、可合并、可清理的状态，不建立给所有地板逐格计时的无限脏度模拟。
- **老化与故障分离**：缓慢磨损、维护欠账和具体故障分别保存；风险随暴露积分，故障模式在触发时确定，普通修理不会让旧设备无条件变新。
- **建造占用**：连续占地、交互组、候选站位、通路和挂点是数据，而不是散落在 Prefab 中的隐式规则；辅助网格不拥有玩法真值。
- **双尺度旅行接缝**：宏观路线进度与固定车辆舞台分离；路线采样区域表现，停靠时进入有限场景，返回主要地点能重建重要状态。
- **分级持久化**：内容定义明确选择永久、聚合、重建或短期状态，不能默认全部保存。
- **数据驱动定义**：居民原型、资源、设施、地貌和事件内容可以扩展，但不为未知未来预建通用编辑器。
- **人和 AI 共用编辑服务**：内容定义稳定后再做一个薄 UI Toolkit 开发窗口；Inspector / 窗口与 AI 批处理调用同一服务，支持查询、校验、Undo 和 Dry Run，不让编辑器 UI 成为第二套业务逻辑。

这些能力先留在游戏独立程序集；只有跨游戏再次成立或 Framework 公共用法被真实阻断时才上提。

### 8.5 v0.1 验收信号

通过需要同时看到：

1. 玩家不用直接操控，也能持续做出影响居民和车辆的决定；
2. 设定目标后，旅途中仍有值得观察和处理的事情；
3. 居民会在多个合理行动间产生变化，但紧急状态不会因随机选择失控；没有工作时，玩家能快速理解原因；
4. 空间布局至少造成一次可见的通路、容量或工作效率差异；
5. 停车下车和重新出发没有变成割裂的两个小游戏；
6. 保存、读取和返回主要地点后，重要状态正确，小细节是否重建不影响信任；
7. 试玩者能主动说出下一步想扩建、修复或探索什么。
8. 玩家能从画面和状态追踪至少一条“获得 → 搬运 → 使用 → 废物 / 污渍 → 处理”的生活链，而不是只看几个需求条自动升降。

若玩家主要在等待、自动居民经常做出无法解释的行为、旅途只剩动态壁纸，或车外作业与车辆经营互不影响，应先重做地基，不进入内容生产。

## 9. 明确延后或删除的设计

### 9.1 下一阶段再考虑

- 人口增长到 6–8 人以及招聘、临时乘客和伤员；
- 洗澡、衣物 / 洗衣、多维卫生、完整士气、性格、爱好、长期关系和差异化压力反应；简单排泄、垃圾、污渍与一次社交恢复不在此列；
- 多部件老化、复杂预防性维护、多个备件类别和连续设施性能衰减；第一版只保留一条可解释故障链；
- 商人、难民、敌对势力、区域供需和声望；
- 多种地貌、天气前线、道路网络和更复杂的侦察；
- 正式前哨、生态恢复、远方抽象产出和世界结局；
- 自动防御、居民岗位式战斗与撤离压力；
- 最终美术、音频、教程、Steam 页面和外部垂直切片。

### 9.2 当前不做

- 直接控制居民或车辆；
- 车辆在主画面中转向、掉头或绕开普通障碍；
- 任意层数、任意悬空结构与复杂楼梯网络；局部两层、可见梯子及三四层验证已进入后续方案；
- 无限世界、覆盖大陆的一比一连续地形或处处高密度的开放世界；
- 任意地点建设完整永久殖民地；
- 保存每棵树、每个小残骸和每次路边随机事件；
- 数十名居民、远程微操多个殖民地；
- 逐格气体、液体和热力学模拟；
- 大规模室内登车战、多人、LiveOps 或运行时生成式 AI。

这里的“不做”是当前产品与原型边界，不是永远禁止。若真实试玩证明某项是解决核心问题的最高价值方案，可以重新评估，但不能因为“以后可能有用”提前实现。

## 10. 已合并和去除的重复设计

- “自由驾驶”和“节点旅行”合并为：在种子宏观地图中设置目标点，路线持续推进；兴趣点只是目的地，固定旅途舞台负责连续表现。
- “塔防”不再作为独立小游戏；未来防御只作为停靠、噪声、天气或敌对行为产生的压力。
- “生态复育”不再单列第二套玩法；未来它使用同一套人员、电力、材料、地面建设与前哨系统。
- “开放世界”收口为有限种子宏观地图；宏大感由未知区域、路径选择、天气、地标和持续旅途产生，不靠一比一地形或无限面积。
- “车上建造”和“地面建造”分工：车上承担移动生存与核心生产，地面承担地点相关的重型或临时作业。
- 多种身体与心理需求分期实现；第一版只保留能改变工作和资源决策的基础状态。
- 世界持久化按重要性分级；“世界记住玩家”不等于数据库记录所有物件。临时停靠点只有在被提升为前哨或重要地点后才长期保留。
- 宏观方向与画面方向解耦：车头和镜头固定，删除车辆旋转、局部驾驶寻路和世界方位遮挡问题。

## 11. 技术与验证重点

第一版最值得自动验证的并不是内容数量，而是系统可信度：

- 固定 Seed 下宏观区域、路线条件和主要地点身份稳定；
- 资源获取、消耗、搬运和建造满足守恒边界；
- 搬运必须从具体库存或地面物堆到具体容器，来源不足、目的地已满或交互位被占时原子失败，不复制、不吞物品；
- 饮水 / 进食产生的排泄物和垃圾进入明确容器或被明确排放；容器满、管道断开与人工清运的后果可以复现；
- 腐败、设施老化、居民疲劳和区域污渍可以共享经过测试的数值数学，但各自的来源、恢复、事件和存档语义不会串用；
- 设施风险积分在不同帧率、暂停、1× / 加速和存档读取后得到同一故障时刻；提高老化、维护欠账、积尘或负载会统计性提高风险，但同一 Seed 可复现故障模式与严重度；
- 生活日与气候相位都可由统一模拟时刻重建；调整季节倍率不会让居民一顿饭或一次睡眠跨越七天；
- 同一 Seed、居民状态和决策序号可以复现相同候选、效用分解与随机结果；不同 Seed 能产生变化，但选择仍落在合理候选范围；
- 饮水、进食、休息等压力接近危险值时会稳定压过低价值休闲，普通工作与休闲不会因候选数量或随机运气永久饥饿；
- 行动承诺、切换成本和事件复评不会造成居民在两个目标间频繁往返；
- 两名居民不会预留同一份唯一材料；
- 建造拖动时能实时显示候选交互位和保守可达性，明显堵路的位置不会等到建成后才暴露；确认后的 NavMesh 事务仍可完整回滚；
- 长时间加速运行没有任务死锁、无人进食或全员卡在召回状态；
- 1× 与加速在允许误差内产生一致的模拟结果；
- 保存/读取前后居民、设施、库存、目标点、路线进度、当前停靠点和主要地点状态等价；
- 离开再返回主要地点时永久状态和聚合状态正确，普通旅途景物与小事件没有被误判为永久；
- 宏观航向变化不会旋转车辆、甲板网格、镜头或车内寻路；
- 旅途表现片段可以稳定复用，长时间运行不持续创建对象或显著增长内存；
- 固定镜头与状态截图能检查车内可读性、遮挡和扩建后的居民尺寸。

自动化只证明系统可靠，不能证明旅途有趣。每个里程碑仍需人工观察：玩家是否理解居民、是否在等待、是否在乎下一处目标、是否愿意为一个人改变路线。

## 12. 仍待原型回答的问题

以下问题不阻塞 v0.1 开始，但需要通过灰盒而不是继续空想锁定：

1. 管理视角采用开放甲板、自动隐藏屋顶还是剖面车厢；
2. 第一阶段底盘尺寸、设施占地和最终可接受的镜头高度；
3. 大地图上的路线、道路、未知迷雾和改道代价如何反馈，才能让固定旅途舞台仍有方位感；
4. 旅途的自然信息密度，以及安静时段需要多少加速能力；
5. 居民受伤、掉队和死亡在正式产品中的惩罚强度；
6. 临时停靠点在什么条件下提升为持久地点，以及这一行为是否需要玩家主动建设信标；
7. 已实现的沙尘→水箱故障→实体维修是否能在旅途中形成可预期的停车决定，还是需要降低频率或改变预警；
8. 普通工作、基础需求与低风险休闲的候选截断比例和随机温度，怎样既保留角色感又不削弱玩家指令。
9. 已选择并实现的水 / 排泄链，接上地点补给和清运后是否能形成值得玩家介入的劳动、容量与路线取舍；
10. 简单社交行为应在 Foundation 的哪个阶段出现，才能提升角色依恋而不把首轮 AI 状态空间放大到难以诊断。

这些问题应进入可替换的 Prototype，而不是提前固化成 Framework 公共抽象。
