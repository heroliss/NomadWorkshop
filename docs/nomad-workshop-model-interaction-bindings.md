# 可替换模型与设施交互绑定

2026-09-08。用户要求当前资产以后可换为 Rodin 等来源的精细模型，并提醒功能锚点的位置、数量及动作配合都可能变化。水设施已实现接触点数量变化、精确工位动作、旋转/平移行程配置，并接入[编辑期空间生成](nomad-workshop-facility-space-baking.md)：模型标记生成站位、占地和放置区域，启动时检查过期数据，保存时记录空间身份。**任意模型自动识别和人物开门同步仍未实现**。三种[正常人物小样](nomad-workshop-character-authoring.md)已形成独立试玩入口。行为证据见各阶段记录；主排期见 [Foundation §9](nomad-workshop-foundation-vertical-slice.md#9-近期队列美术样板与可扩建建造)。

## 目标与制作取舍

模型替换的常见工作应收敛为：导入模型 → 在外层 Prefab 绑定功能角色、调整站位/区域/动作参数 → 运行同一组验收。玩法不依赖模型来源、子节点名称或固定锚点总数。新增一种模型不应新增一个设施专属行为类；新增一种交互机制才可能需要新的可复用实现。

已停止精修被否定的方块人物衣物与背包附件。人物现沿用正常蒙皮角色制作工装；水罐在模型绑定建立的同时制作第二种明确不同的外观，用真实拿放和倾倒验证替换。美术时间优先用于能跨模型保留的灯光、材质方向、镜头、HUD、绑定工具和行为验证。当前 `NomadWorkshopResidentArtPipeline` 的身体分区/附件生成只属于旧占位资产配方，不是任意新角色的导入器。

共享 Humanoid 动作、导航、物品身份、资源账本、行动阶段和暂停/恢复语义可以保留。新角色仍需要有效 Avatar、蒙皮和正确朝向；只有网格不能直接播放现有骨骼动作。人物身材、手柄高度、门轴或桌面尺寸变化仍需配置和可达性检查，不能承诺任意模型零校准。[NW11 水罐](nomad-workshop-watercan-art-and-posture.md)已将几何接口与地面下蹲位移移入同一容器绑定；其中的姿态输入仍只服务已验证角色，不能当作自动适配任意身材的结论。

## 空间数据与动作配合分开

用户提出的点、区域和匹配动画分别覆盖了几何与行为。采用可组合的几类数据，避免把整个设施限制成其中一种类型：

| 数据 | 内容 | 示例 |
|---|---|---|
| 接触点 | 稳定局部 id、语义角色、所属工位、Transform 位置/方向、可接受接触范围 | 锅中心、右手握点、门把手、出水口、粒子发射点 |
| 支撑区域 | 稳定 id、所属工位、局部支撑平面、边界、朝向与物品限制 | 桌面、柜内层板、水罐停车区；物品容量由占地与预留决定 |
| 活动分件 | 稳定 id、Transform 引用、真实枢轴、旋转/平移方式、局部轴、行程与静止姿态 | 平开门、滑盖、抽屉、阀门；同类机构复用实现 |
| 交互动作配置 | 所需角色、适用工位、阶段、人物动作语义、接触权重和分件/特效进度曲线 | 开门、拿放、操作、灌注；一个动作同时消费多个点与分件 |

接触点本身不拥有物品、不等于站位、不增加并行人数。炒菜的锅中心、左右手目标与火焰点可以同属一个容量为 1 的工位。角色仍站在经导航验证的 Slot 上，通过有限的对齐/IK 接近目标。

同角色的点可以有多个，但不能用“数组第一个”或“最近 Transform”猜配对。每个实例有稳定 id；动作以精确工位和当前 Slot 解析对应角色集合，声明必需、可选和数量约束。两个龙头共用一个狭窄操作区，可以仍只有一个交互组；确实允许两人并行时才创建两个工位组，并检查共享门、容器或机构的互斥。增加装饰/特效点不影响玩法容量。业务选择先由所需能力筛出候选工位，再按可达性/租约取得精确 id，表现消费同一个选择；当前单组常量向这一形式迁移时需跑业务回归。

桌面首版继续使用现有有向矩形区域，可组合多个小区域近似复杂桌面；不急着做任意 Mesh 表面采样或物理堆叠。区域内的精确落位仍由 `PlacementRegionLedger` 裁定。模型中的区域标记是编辑输入，运行期视觉碰撞或物理下落不是第二份库存真值。

NW5 车体制作提供了一个具体边界：按材质合并的驾驶舱 Mesh 同时含车首和车尾牵引环，其 Renderer AABB 横跨可行走甲板，但中间没有对应实物。P1 的占地/支撑生成不能直接把整组渲染 Bounds 当成实心几何；应使用显式标记或审查过的分部件简化形状。详见[结构造型实机记录](nomad-workshop-reference-form-study.md)。

## 配置来源、坐标与替换流程

采用编辑期绑定生成并校核空间快照，继续使用现有纯模拟与事务；运行时不以逐帧模型扫描覆盖空间真值。模型与定义的校验和保存边界见 [P1 实际流程](nomad-workshop-facility-space-baking.md)。

1. 保留一层米制、单位缩放、脚底/底座原点明确的玩法外壳。导入 Mesh、材质和骨架放在可替换子树；绑定放在游戏自有包装 Prefab/变体中。外部生成器的节点名只属于该来源的导入 Adapter，运行逻辑不依赖它。
2. 一份绑定配置拥有模型相关空间输入：接触点、分件、工位候选、支撑区域与简化占地。使用显式 Transform 引用，名称识别只能帮助首次建议绑定；不把推测结果静默当作正确值。
3. Editor 将静态站位、区域和占地转换到设施根坐标，校验后生成现有定义快照。记录来源与版本/内容摘要；过期快照不能悄悄进入验收。运行期模拟只读取生成结果，表现读取与之匹配的绑定。
4. 使用三维局部 Pose 描述接触，保留层/支撑面身份。当前单层 `DeckPose` 的平面工作位仍由明确转换生成；不把手柄高度塞成另一层，不以世界 Y 猜层。跨层扩展承接[甲板方案](nomad-workshop-expandable-decks-design.md)。
5. 运动部件上的把手随部件变换，站位和净空不会因为动画而每帧重烘焙。需要门扇扫掠/通行开闭的玩法，通过专门的空间状态和租约处理；不能只让门 Mesh 旋转就当作通道已经打开。
6. 模型替换在 Editor 或下一次重建表现实例时完成，不做持桶动作中热换资产。只换外观且保留空间与稳定 id 时可复用原存档；修改工位数量、移除旧区域或改变占地时，按空间定义版本显式迁移、重新验证或拒绝不兼容旧布局，不静默挪走玩家物品。

替换模型仍要在共用工具中标注新位置。系统的“适应能力”是把校准做成配置、限制检查和有解释的反馈，不能从任意精细网格可靠推断哪块是可开门、哪面桌子允许放锅。后续可加候选识别，但先有人工/脚本可审查的正确绑定。

## 人物与机构的同一动作进度

以开门取物为例，动作可描述为：取得工位/门口租约 → 到达站位 → 伸手接触把手 → 门转动且手跟随移动把手 → 取物 → 松手/退出 → 关门并释放租约。具体动作并非所有设施都要走完全部步骤，可以从少量复用动作配置组合。

System 拥有阶段、资源提交点和中断语义；读模型发布动作实例、准确参与者和绝对进度。人物动作、IK、门扇与声音/特效都消费该进度。表现不从 Animation Event 结算库存，不用独立 Tween/动画时钟决定何时允许通行。只修饰节奏的曲线属于表现配置；影响占用/通行/资源提交的时序必须属于逻辑定义。

当前维修盖属于暂时工作反馈，取消后可回到静止姿态；玩家可留开的门若会改变导航与天气，开闭状态必须进入业务状态。不能把两者都做成“无人操作就自动归零”。暂停、取消、删除设施、读档与租约失效各自需要明确终态；先复用现有任务释放与读档规范化，不立即实现任意动作中点的完整恢复。

IK 只修正有限范围内的接触。绑定验收要检查实际掌心/脚底、臂长、全段身体/道具净空和门扇扫掠；超出可达范围时反馈需要改站位、换动作或改模型，不拉长手臂掩盖错误。真正开门的人物动作仍需基础 Clip/姿态制作，给门一个旋转曲线并不能自动生成自然的人体运动。

## 可检查的实施计划

以下实现项按依赖推进。除已完成的审查外，均不冒称已经具备通用模型替换能力。

2026-09-06 的 P0 阶段范围：P0 与 P2 中已有旋转/平移机构的参数化。实际调用链为有效工位租约 → `FoundationFacilityWorkState` → `NomadFoundationWorldView` → `FoundationFacilityArtRig`；资源交接继续归 System 所有。比较新增一套独立绑定组件与深化现有 ArtRig 后，选择后者：动作绑定按精确组/Slot/阶段解析，接触点有稳定 id 与用途，机构保存局部轴/行程，继续由同一绝对进度投影。旧水箱/饮水站配置入口只负责生成默认配方，不在逐帧投影中按设施种类分支；旧 Prefab 的序列化引用保留为过渡输入。该 P0 阶段未修改站位/区域、库存或存档格式；后续 P1 结果见空间生成记录。

## NW4 实际变体与阶段边界

入口为 `Assets/Game/NomadWorkshop/Scenes/FacilityBindingSample.unity`，菜单“Assets/SSFramework/游牧工坊/首版美术/生成并打开设施绑定变体”。原三居民场景与 NW1 设施保留。变体将水箱出水点横移 0.16 m、入水点横移 -0.22 m，阀门反转 95°、检修盖行程改为 0.58 m；饮水站入水点横移 0.11 m、提高 0.04 m，顶盖改为侧铰链，并给动作增加可选特效点。可选点只验证数量变化，不产生额外工位或特效行为。

静态管件在旧 FBX 中已按材质合并，生成器不能按 Blender 制作阶段的零件名移动它们。本实验保留原静态网格，增加可见接管与调整真正分件的枢轴；它是绑定用几何变体，不是精细美术替换。后续模型制作应保留需要活动或单独校准的结构。接触点 id 的作用域为动作绑定，水流明确选择端点 id；相同组/阶段的通配 Slot 与具体 Slot 重叠会拒绝，不依靠数组顺序。

首次运行暴露生成资产跨 Single 场景切换后引用失效，落盘的两个设施定义为空。修复为跨场景仅保留路径/id，接线时重新加载持久资产，保存后重新打开并检查全部设施引用。首次 14 项 SetUp 失败结果保留在 `checkpoint-binding-play`；修复后 `checkpoint-binding-play-02` 为 **14/14 Passed**，job `d1711fc67a52`，58.04 s，覆盖原工坊 12 项、居民身份保持及变体实际接口/旋向。绑定边界 EditMode 为 **11/11 Passed**，job `bbde8eb409c1`；首轮一个测试误用四元数逐分量完全相等，改为检查复位后的实际角差，保留失败记录。

以上 P0 证明两种水设施在原空间定义下替换绑定后仍可执行同一工作。后续支撑区域与站位生成已由 [P1](nomad-workshop-facility-space-baking.md) 接入；任意设施的能力到工位解析、必需动作全集推导、可视化绑定工作台、多组并行水流、门扇通行/天气语义及人物移动把手跟随仍待实现，不能将这些阶段等同于完整通用建造或开门系统。

阶段收尾复测：旧 Warm 12/12（3ee016eb22c1）、NW4 14/14（f12d74b1d1d8）、绑定 EditMode 11/11（d59d3c3fd770）。旧资产回归暴露 Unity 热重载保留派生缓存为空数组；缓存、端点与静止姿态显式 NonSerialized 后，新旧入口分别通过。装水和倾倒实际截图已查看：新接管、水流端点和侧开盖可见，掌心误差约 1.0 mm、角差约 1.45°。水罐与设备外形仍偏简化，水流是表现曲线；本轮不作为达到参考图美术水平的验收。最终恢复干净非 Play 的 ResidentCrewSample。完整范围见[阶段检查点](nomad-workshop-stage-checkpoint-2026-09.md)。
