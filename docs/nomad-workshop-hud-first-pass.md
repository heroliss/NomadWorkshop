# 游牧工坊：首版玩家 HUD

接续 `37acaa2`，为当前三居民与首段旅程提供可直接试玩的常驻信息和操作。仍采用已接入读模型/Command 的 IMGUI View，统一外观与布局；不为视觉样板重写业务或同时迁移 UI Adapter。

## 可检查计划

- [x] 左上常驻三居民选择、当前工作、水分/健康/精力/心情；缩短多层点击，不生成会被更换人物废弃的肖像资产。
- [x] 右上常驻水箱、饮水站和燃料，保留旅程/居民/建造/开发入口；右下提供日期、天气、暂停与倍速，存读档忙碌时沿用真实禁用语义。
- [x] 用深灰绿、暖白和黄铜色统一按钮、选中态、面板和文字层次；主题资源由 View/Bag 拥有，退出场景恢复全局 GUI 状态。
- [x] 绘制与世界输入共用缩放和矩形；小窗口按至少 960×540 的逻辑布局等比缩放。面板不能挡住常驻时间控制，透明区域不吞世界输入。
- [x] 普通建造文案说明设施与通路；最近一次预检诊断保留在开发面板。保持建造 Command 顺序、剖切和存档契约。
- [x] 验证真实 UI 入口的暂停/倍速/居民切换、检查点忙碌与恢复、缩放输入、资源更新及既有搬运/旅程；检查至少两种窗口尺寸下的 Game 截图。

HUD 不新增业务状态或存档字段。角色选择、面板和视觉主题属于观看会话，所有模拟操作仍通过既有 Command。环境与设施的造型继续按 Foundation §9 推进，不将 HUD 改善当作整套美术已经完成。

## 实现与观看边界

`NomadFoundationDebugView.PlayerHud.cs` 保留常驻卡片与时间按钮；主文件继续负责只读订阅、详细面板和建造交互。居民按钮沿用可替换的局部订阅 Bag；点击标签不复位居民、不创建第二份个人状态。水箱与饮水站分别显示实际库存，让玩家看出水仍需要搬运，燃料按原单位换算为 L。

暂停按钮和空格调用同一入口；仅在模拟就绪且没有存读档操作时生效。空格检查 IMGUI 键盘控件占用，避免输入控件收到空格时再触发全局暂停。倍速不会自行解除暂停。右侧详细面板在资源卡下开始，在时间卡上方结束，内容不足以全部显示时沿用滚动区。

`FoundationHudTheme` 克隆源 Skin，创建五张 12×12 九宫格纹理，资源全部交给当前 View 的 Bag。不会修改借来的皮肤；OnGUI 的 `finally` 恢复本次修改的全局 Skin、matrix、color 和 enabled。按钮、面板、字体只是表现，不属于模型、存档或通用 Framework 公共 API。

布局以 960×540 为最小逻辑画布；更小窗口等比缩小，世界输入按同一倍率反算。当前是桌面鼠标/键盘样板，800×450 可操作但文字偏小，不据此宣称移动端、高 DPI 或可访问性验收已经完成。常驻居民栏以当前三人为设计范围，人口增长时应再设计列表或头像条。

## 后续定位：工作结束后的让路窗口

“固定半径找不到空地”的初始判断没有得到几何对照支持，因此没有扩大搜索圈或放松净空。继续审查发现，两秒轮询可能错过占位者完成爱好后的短暂空闲；下一次轮询时，该居民已经重新领取同一个工位。这与原失败中驾驶员等待、其他居民继续完成休闲的表现一致；原失败帧未记录整个交错，不能声称逐帧还原了那次随机实机时序。

新增 `NativeCohort_FinishedHobbyAnswersWaitingDriver_BeforeRebookingItsSlot` 明确控制该交错，先用真实决策、租约与到岗建立爱好行动，再切到原生 Agent；其后仅对齐请求轮询与工作剩余计时。修正前 job `e53c1f7b3903` 在预期断言失败：居民 03 再次 EnjoyingHobby，居民 01 继续 MovingToDriver / TrafficWaiting。修正后定向 job `9e74b3f1c1cc` 通过，观察到让位、驾驶员实际到岗，爱好完成数只增加一次。此后将回应检查放在原有决策重试时机内，完整回归包含最终实现。

修正让 Idle/WaitingForFacility 居民在选择新行动前，优先响应近处已有路径且已等待的居民；复用原来的候选、租约保护和身体路线检查。失败搜索不增加每小步寻路开销，也不清零请求者的个人停滞。无可执行请求或使用同步角点 Soak 时直接沿用原决策。
