2026-09-06，承接[首版美术样板](nomad-workshop-art-first-pass.md)。本轮回到 S0 的实际生活与维修画面，先让可见分件响应真实操作，再继续人物拾放和顶棚显示。完整多层、围护与天气仍按 Foundation §9 推进。

## 可检查计划

- [x] 由居民当前有效工作位租约发布设施、功能组、阶段和进度；行走、取消及恢复后不留下旧操作投影。
- [x] 在 Blender 资产中提供有正确轴向的阀门、检修盖和注水口；保留源文件、导出与 Unity 回读验证。
- [x] 水箱装水、饮水站接水与水箱维修使用实际实例和绝对业务进度驱动分件；暂停冻结，恢复不重放旧动作或影响库存。
- [x] 通过真实场景验证两座同类设施不会一起动作、携物唯一、暂停/恢复与取消，并查看俯瞰和操作近景。

## 所有权

System 从有效 InteractionSpace 租约提取精确设施与功能位，形成居民的只读工作投影。表现不能从人物附近或任务中文字符串猜目标，也不能把预留/走向设施当作已经开始操作。已有计时器拥有进度，View 不开第二只累计动作时钟；动作不提交资源。

模型分件和锚点由资产定义提供，几何回读时校核位置与方向。View 只调整这些可见部件与同一只水罐的表现姿态，业务坐标、设施占地、工作位与库存不随动画改变。新工作投影是派生状态，不增加存档字段；恢复先依照现有事务规范化任务，再生成新的投影。

当前 `FoundationFacilityArtRig` 仍是水箱/饮水站的固定字段适配，不是已经完成的通用锚点系统。后续模型可能改变接口位置、数量与机构方向，按[可替换模型与设施交互绑定](nomad-workshop-model-interaction-bindings.md)推进：接触点、支撑区域、活动分件分别配置，以工位身份和共同动作进度配合；模型相关空间配置经校验生成逻辑定义。

## 已接线的行为

`FoundationFacilityWorkState` 以一次快照发布实例 id、功能组、工作位、阶段和进度。`FoundationFacilityArtRig` 不持有 Context 或独立 Update；WorldView 每帧复位后，按精确设施实例应用所有居民的有效操作，同一设施上的不同功能组仍可分别工作。

水箱装水时转动阀门、连接实际水罐并显示短水流；饮水站接水与驿站回水时打开对应补水盖，同一水罐绕握点抬起倾斜。手部 IK 跟随水罐的实际把手。维修打开上滑检修盖，避免旋转门扫过后方两个维修位；维修包和维修计数仍在原业务提交点结算。

Blender 配方 v0.6.1 的九类资产共 **68,469 三角形**。水箱有六个工作/状态锚点，饮水站有三个；Unity 导入验证锚点位置、三轴、原点相对 Bounds、三角形和源文件哈希。水箱增加局部警示灯：故障亮红、临界亮橙，完成维修后熄灭。普通美术外壳保留材料区别并轻微积尘；建造模式继续使用强可达性着色。水流和警示灯不被外壳积尘覆盖。

机械动作使用进度包络，管线为受控曲线和短水流，尚未实现软管物理与手动拿喷嘴。后续[人物接触迭代](nomad-workshop-resident-contact.md)已补充水罐掌心方向、肘部净空、站姿倾倒及独立侧面地面拾放，并扩展美术场景到 12/12；本页上述照片与 8/8 记录保留设施阶段的原始证据。维修工具握持和其他道具拾放继续制作。其余设备、局部顶棚、切层和 HUD 不在本轮完成范围。未做目标 Player 构建、性能基线或新的物理输入验收。

## 验证边界

自动检查关注精确实例、真实阶段、分件确实运动、暂停一致、旧表现释放及资源守恒。近景另看手掌可达、阀柄/检修盖轴向、软管/注水口位置和设施辨认。单个阀门角度检查不能代替实际使用链，机械反馈通过也不能声称人物拾放和整体美术已完成。
