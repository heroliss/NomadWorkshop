## 当前观察与约束

掌心迭代开始时，手部 IK 只把腕骨拉到把手中心，没有掌心方向和肘部提示；装水和倒水还映射到通用 Work，实际选择 `Armature|Fixing_Kneeling`。现在装水/倒水使用站姿，维修保留跪姿；工作阶段不再被行走速度的平滑尾部覆盖。后续地面拾放已经接入独立工作位和计时阶段，当前验证进度见文末。

掌心标定由完整 Humanoid 的中指根、食指根和小指根建立，避免假设 FBX 的腕骨局部轴。把手提供独立的表面目标；动画骨架仍拥有身体姿态，物品几何与业务落位不反过来跟随错误腕骨漂移。通用杯具/维修包与污物桶的接触形状不能直接套用水罐把手。

Humanoid 的 IK Goal 坐标与源 FBX 腕骨坐标还有固定旋转差；首次 IK Pass 在施加约束前标定一次。验收测量实际腕骨变换后的掌心表面与朝向，不使用目标 Transform 自证接触。水罐由同一个表面目标驱动手掌和指部握持层；肘部候选位于双骨长度决定的圆上，按罐体加 3.5 cm 净空寻找可行弯曲方向。自动检查另测实际上臂/前臂与罐体加 3 cm 的体积边界。

持罐握点向身体外侧移出大腿范围；倒水抬到肩部附近并倾斜 100°，不再额外向前推到臂长之外。连续验证覆盖抬桶、倾倒、回到携行姿势三个区间，要求掌心残差小于 1.5 cm、朝向误差小于 4°，并检查实际身体胶囊和双臂净空。这些约束是当前共享角色与水罐的样板，不承诺任意身材/道具自动适配。

楼梯使用同一握持标定。完整罐体外缘的平面携行半径约 0.641 m，实验导航半径改为 0.67 m，身体胶囊仍为 0.2 m；只有自有实验 Agent 配置经 Editor 迁移。正式单层导航目前没有按所携道具动态改变通行半径，门洞、两人携物交会和侧面拿取位需后续一起验证。

本轮优先处理上肢接触与可验证过渡，不把局部 IK 宣称为完整角色美术。跨层正式库存、梯子互斥与施工仍按 Foundation §9 推进。

## 拾放前先修正站位契约

核对正式设施定义后，水箱水罐停放区域位于设施局部 `(1.2, 0)`、饮水站位于 `(.72, 0)`，支撑高度均为地面。原 `GetWaterCanAccessInteractionGroup` 复用正面装水/饮水工作组。例如水箱右侧装水位为 `(.48, -.9)`，与水罐的水平距离已经约 1.15 m，还未计入肩高到地面把手的高差。倾倒后也直接把水罐投影到该侧面区域。这是业务站位与物品接触不一致，不能靠延长手臂或仅在 View 插值补救。

实现按以下顺序推进，同一批路由改动需要复验 Foundation；完成项以下面的检查清单和实机证据为准：

1. 为侧面停放区定义独立的 `water-can-access` 工作组，使用现有空间租约保证身体站位互斥。保留现有停放区域与局部存档姿态；检查站位到真实把手的可达性、设施壳体净空及绕行路径。
2. 拿取先到侧面，面向实际物品，蹲身/伸手接触，再由模拟计时器提交领用并抬起。取消“水罐在水箱旁就省略前往装水位”的快捷分支，取得空罐后实际走到装水位。
3. 倒水完成后保留空罐所有权与后续饮水/外勤归还意图，预留精确停放姿态，再实际走到侧面并落罐。落位提交后才松手、释放预留与本次工具使用；不能让另一居民在画面仍握持时领取同一水罐。
4. 工作快照发布身份、来源/已预留目的地和业务进度，View 从快照求姿态。取消/故障/死亡/读档必须释放旧快照和预留；暂停与建造事务保持同一模拟时间。检查点继续规范化未完成动作，不添加第二份容器或让 Animation Event 结算水。
5. 实机验证“地面接触 → 抬起 → 到装水位 → 满罐搬运 → 倾倒 → 到侧面 → 落罐 → 松手”，覆盖旋转设施、第二座饮水站、被占站位与中途恢复。近景记录站位、实际掌心、物品身份、落点和库存提交点。

低位接触需要身体下蹲和支撑脚约束；它与站立持桶的手部 IK 分开验证。运行期骨骼姿态不改变导航拥有的身体位置，物品的几何支撑位置仍由区域账本确定。
