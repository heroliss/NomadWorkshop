# 持桶跨层通行实验

本实验服务于可扩建甲板 S2 的技术验证，不把正式单层玩法提前声明为多层。复用正式 Humanoid、携物 IK、水罐几何与原生移动 Adapter；实验状态不进入正式存档。

## 本轮可检查计划

- [x] 两个相隔 3.2 m 的真实平台、18 级踏面与护栏；导航和身体碰撞使用同一几何。
- [x] System 拥有带高度的路线、身体位置和实验中唯一的 8 L 水罐；View 只投影与发送命令。
- [x] 复用移动动画，以踏面查询和小幅骨盆修正保持足部可达，右手保持同一个桶把手。
- [x] 验证上楼、下楼、半途暂停/继续、取消、带高度的检查点恢复及错误楼层拒绝。
- [x] 真实场景截图与逐用例证据落盘；检查正式携物、导航调用方回归。

后续独立验证直梯的双手需求、入口出口互斥和安全端点取消；水桶走楼梯，直梯只接受空手或背负。再验证局部楼板与切层显示；隐藏 Renderer 不停用物理、导航和模拟。

2026-09-07 用户提醒车内楼梯需要紧凑布局，长直梯继续保留为动作基线。[折返尺寸小样](nomad-workshop-reference-form-study.md)沿用既有 1.65 m 踏面宽与 0.67 m 携物半径，初步得到 3.52 × 4.35 m 的踏面/平台外包框：缩短长边但增大宽度和总面积，尚不能视为最优车内方案。2026-09-08 已完成[实际折返梯实验](nomad-workshop-switchback-spike.md)，独立验证平台转身与满罐往返；后续仍需结合车内入口、上层开口及设施布局判断尺寸，不缩小载物包络来替代验证。

## 所有权与边界

路线由 NavMesh 规划，CharacterController 提交最终身体位置。带台阶的移动配置按实例显式启用，正式平面居民默认不跨台阶。末段到岗检查使用三维误差，平面投影一致不代表抵达另一层。

独立 Agent 类型 `Nomad Stair Carrier` 使用携物净空半径 0.67 m、身高 1.8 m、最大跨高 0.22 m、坡度 40°。实际躯干胶囊半径为 0.2 m；携行净空不能直接变成更宽的球形胶囊底部，否则会提前顶上前方高踏面。生成菜单沿当前 Unity NavigationWindow 的序列化接口增加此类型，不更改原 Humanoid 类型；重复生成复用并核对参数，只迁移明确匹配的自有旧实验配置（0.2/0.4/0.65 m）。采样与路径查询显式携带当前 Surface 的 Agent 类型。导航跨高不能比胶囊体跨高大，否则可能规划从楼梯侧面直接踏上身体够不到的高度。

脚部 IK 只负责表现，查询范围限制在脚边，避免直接命中头顶平台。支撑脚贴地，摆动脚保留动画；骨盆修正最多覆盖两个踏步的高度差，下降时额外防止摆动脚穿进前方高踏面。目标误差在 Animator 求解后的 LateUpdate 读取，避免把本帧逻辑根和上一帧 IK 目标相减。水罐的握点由共享 Avatar 的肩高与臂长标定。IK 失败不能触发到岗、扣水或移动逻辑根。

实验检查点只包含已提交身体位置、朝向、目标层、暂停和携水量；恢复先验证版本、范围和导航高度，候选身体绑定成功后才撤销旧移动实例，重建同一意图。它不是正式保存协议的升级，不证明旧游戏存档已支持多层。

Unity API 依据：[CharacterController.stepOffset](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/CharacterController-stepOffset.html)、[Animator.SetIKPosition](https://docs.unity3d.com/6000.0/Documentation/ScriptReference/Animator.SetIKPosition.html)。最终是否成立以本项目实机行为为准。

## 验证记录

首轮 `91cdd9c1f21d` 为 0/4，完整失败证据在 `Logs/AIValidation/nomad-warm-art/stair-playmode-01/`。发现原 Humanoid 烘焙跨高 0.75 m 与实验身体 0.22 m 不一致，且 NavMesh 高度误差被计入水平移动限速，导致频繁重锚与低速。另有一条测试用字符串替换浮点数来制造无效高度，因序列化精度差异未实际改坏输入，已改为明确的无效数据。

修复后实际往返用例 `3019a3d738f3` 为 1/1，全夹具 `0a2a1812d7bf` 为 4/4。近景进一步发现单脚约 7.7 cm 的目标残差与躯干半径导致的贴扶手问题，因此加入骨盆修正和携物净空，阶段夹具 `caab05636aa0` 为 4/4。再次查看近景后发现摆动脚被过度约束，遂区分支撑/摆动并将足骨实际到达检查扩展到整段路径；`640a61bceb72` 与 `41b036fad78c` 各为 1/4，证明先前单个暂停点通过仍不足。最后根据真实前后脚的踏步高度差修正骨盆限幅。所有失败证据保留，不以新绿灯覆盖。不能只测 IK 权重为 1 就声称脚已接触踏面。

这仍是固定两层结构与固定携水量的实验，不包含正式水源/目的库存交接、楼板施工、直梯互斥或正式跨层存档迁移。脚步先以共享行走 Clip 加 IK 验证可行性，后续仍需处理落脚节奏、动作过渡及更自然的负重姿态。

该阶段楼梯夹具 `9ba48a9e5bea` 为 **4/4，67.15 s**，精确证据在 `Logs/AIValidation/nomad-warm-art/stair-playmode-06/evidence.json`。[该阶段持桶近景](../Screenshots/nomad-stair-carry-close.png)已查看：身体由真实移动来到 1.404 m 后暂停，左脚为支撑脚，右脚保留摆动。该帧右手与把手、左足与目标的误差均小于 1 mm；整段路径检验支撑足目标误差小于 4.5 cm、水罐携行体积不穿楼板/台阶/扶手。图片仍是动作原型，不声明最终角色美术或自然步态已完成。

共享代码的基础回归还引出[取水请求与居民自动返程的边界](nomad-workshop-stop-resource-ownership.md)。定向复现已证明并修正自动返程误清玩家请求；最终 Foundation **102/102**（`bac603ea947d`，323.28 s），美术场景 **4/4**（`0c545797153e`，6.42 s）。精确证据分别为 `foundation-regression-04/evidence.json`、`playmode-10/evidence.json`，都位于 `Logs/AIValidation/nomad-warm-art/`。

旧导航实验的兼容性检查首轮为 **0/2**（`b515d1d19ba3`），均在初始化失败。类型一致性断言进一步稳定复现：新建居民默认采用 `-1372625422`，该实验 Surface 仍是 `0`（`146dc44105ef`，0/2）。旧工厂现在显式把 Surface 类型传给两名 Agent，不依赖新建组件的默认项目状态。最终两人会车、排队开柜与真实物品交接 **2/2**（`65754021d28a`，3.46 s），证据为 `navigation-regression-02/evidence.json`。这项修正只影响旧隔离工厂，正式居民和楼梯实验此前已显式配置类型。

本轮还补充了 [MCP Console 采集停滞时的后备取证](../AGENTS.md)：菜单返回和事件缓冲各自有观察边界，保留同一实例的新 `Editor.log` 段与时间，不能把旧 READY 当本次预检，也不因日志停滞重复写操作。相关协作文档同步，未改第三方 Package 或新增常驻规则。

后续[设施工作反馈](nomad-workshop-facility-feedback.md)为共享水罐增加了位于把手前侧的注水颈。改后楼梯复验 **4/4**（`1b80ce34b8aa`，67.08 s，`stair-playmode-07/evidence.json`），美术场景 **8/8**，Foundation **102/102**；仍未扩大本实验的多层施工或正式存档范围。旧近景反映上轮罐口几何，本次变化的近景与来源哈希见设施反馈记录。

[掌心接触迭代](nomad-workshop-resident-contact.md)随后修正了水罐与大腿的相交，完整携行半径随之增加。当前导航半径 0.67 m 经实际罐体全部网格 Bounds 核对；连续路径同时检查掌心位置/朝向、支撑足误差，以及包含身体胶囊的完整罐体碰撞。最终复验 **4/4**（`0cf419fcef20`，74.23 s，`contact-stair-03/evidence.json`）。

[当前掌心接触近景](../Screenshots/nomad-stair-palm-contact.png)已实际查看，报告 `contact-visual-02/stair-report.json`：身体高度 1.401 m，右脚支撑、左脚摆动，掌心残差约 1.05 mm、朝向误差约 1.71°。该帧与完整路径测试一起支持当前水罐/角色组合的可行性，地面拾放、负重节奏与角色美术仍继续制作。
